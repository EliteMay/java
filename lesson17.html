シーケンス図と複合フラグメント

第21章　シーケンス図の基本 ／ 複合フラグメント（alt・loop）

今日の主役

シーケンス図　複合フラグメント（alt・loop）

今日できるようになること
  • コードを読んで、呼び出しの順にシーケンス図を描ける
  • 呼び出し（実線）と戻り（破線）、実行仕様（細長い四角）を描き分けられる
  • コードの if を alt の段に、while を loop の枠に置き換えられる
① 今日の主役

UML での意味

言葉意味
シーケンス図オブジェクトどうしのメッセージ（メソッドの呼び出し）のやりとりを、時間の順に上から下へ表す UML の図。
複合フラグメント（alt・loop）シーケンス図で、条件による分かれ道（alt）や繰り返し（loop）を表す枠です。枠の中に [ ] でガード条件を書きます。

たとえで言うと

シーケンス図は「舞台の台本」

誰が、誰に、どの順でセリフを言うか。時間は上から下へ流れます。

台本は上から読む。上にあるセリフほど、先に言う

台本には、誰が誰にセリフを言うかが、言う順に上から書いてあります。上にあるセリフほど、先に言います。

シーケンス図も同じです。横に並ぶのが登場するインスタンス、縦が時間です。今日描くアプリでは、画面（ProductFrame）が店長（ProductService）に頼み、店長が倉庫係（ProductDAO）に頼みます。その順番を1枚に描きます。

第16回のクラス図は「どんなクラスがあるか」を描く図でした。シーケンス図は「それらが、どの順に呼び合うか」を描く図です。

台本の「雨なら〜、晴れなら〜」が alt、「この場面を3回くり返す」が loop

台本には「雨ならこのセリフ、晴れならこのセリフ」「この場面を3回くり返す」といった書き込みもあります。シーケンス図でこれを表す枠が、複合フラグメント（alt・loop）です。

たとえJava では
役者ヘッダーとライフライン　:ProductFrame など
セリフ呼び出しの矢印（実線）　findAll()
返事戻りの矢印（破線）　List
役者が話している間細長い四角（実行仕様）
台本を上から読む上にある矢印ほど、先に起きる
「雨なら〜、晴れなら〜」の書き込みalt。Java の if に当たる
「この場面を3回くり返す」の書き込みloop。Java の while に当たる

なぜ必要か

シーケンス図どのクラスがどの順にメソッドを呼び合うかを、コードを追わずに一目で分かるようにするためです。
複合フラグメント（alt・loop）if や while の動きも図に描き、どの条件でどの呼び出しが起きるかを示すためです。

package lesson17;

import java.awt.BorderLayout;
import java.awt.GridLayout;
import java.sql.SQLException;

import javax.swing.JButton;
import javax.swing.JFrame;
import javax.swing.JLabel;
import javax.swing.JOptionPane;
import javax.swing.JPanel;
import javax.swing.JScrollPane;
import javax.swing.JTable;
import javax.swing.JTextField;
import javax.swing.table.DefaultTableModel;

public class ProductFrame extends JFrame {
    private ProductService service = new ProductService();
    private DefaultTableModel model =
            new DefaultTableModel(new String[] {"ID", "商品名", "価格", "在庫"}, 0);
    private JTable table = new JTable(model);

    private JTextField idField = new JTextField();
    private JTextField nameField = new JTextField();
    private JTextField priceField = new JTextField();
    private JTextField stockField = new JTextField();

    public ProductFrame() {
        setTitle("商品在庫管理");
        setSize(480, 360);
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        setLocationRelativeTo(null);

        JPanel form = new JPanel(new GridLayout(4, 2));
        form.add(new JLabel("ID（更新・削除で使う）"));
        form.add(idField);
        form.add(new JLabel("商品名"));
        form.add(nameField);
        form.add(new JLabel("価格"));
        form.add(priceField);
        form.add(new JLabel("在庫"));
        form.add(stockField);

        JButton addButton = new JButton("追加");
        JButton updateButton = new JButton("更新");
        JButton deleteButton = new JButton("削除");
        JPanel buttons = new JPanel();
        buttons.add(addButton);
        buttons.add(updateButton);
        buttons.add(deleteButton);

        add(form, BorderLayout.NORTH);
        add(new JScrollPane(table), BorderLayout.CENTER);
        add(buttons, BorderLayout.SOUTH);

        addButton.addActionListener(e -> addProduct());          // 図2 追加を押す
        updateButton.addActionListener(e -> updateProduct());
        deleteButton.addActionListener(e -> deleteProduct());
        showList();
    }

    private void addProduct() {
        try {
            String name = nameField.getText();
            int price = Integer.parseInt(priceField.getText());
            int stock = Integer.parseInt(stockField.getText());
            service.add(new ProductDTO(0, name, price, stock));  // 図2 add(p)
            showList();                                          // 図2 showList()
        } catch (NumberFormatException e) {
            JOptionPane.showMessageDialog(this, "価格と在庫は数字で入力してください");
        } catch (IllegalArgumentException e) {
            JOptionPane.showMessageDialog(this, e.getMessage()); // 図2 理由を表示
        } catch (SQLException e) {
            JOptionPane.showMessageDialog(this, "データベースのエラー: " + e.getMessage());
        }
    }

    private void updateProduct() {
        try {
            int id = Integer.parseInt(idField.getText());
            String name = nameField.getText();
            int price = Integer.parseInt(priceField.getText());
            int stock = Integer.parseInt(stockField.getText());
            service.update(new ProductDTO(id, name, price, stock));
            showList();
        } catch (NumberFormatException e) {
            JOptionPane.showMessageDialog(this, "ID と価格と在庫は数字で入力してください");
        } catch (IllegalArgumentException e) {
            JOptionPane.showMessageDialog(this, e.getMessage());
        } catch (SQLException e) {
            JOptionPane.showMessageDialog(this, "データベースのエラー: " + e.getMessage());
        }
    }

    private void deleteProduct() {
        try {
            int id = Integer.parseInt(idField.getText());
            service.delete(id);
            showList();
        } catch (NumberFormatException e) {
            JOptionPane.showMessageDialog(this, "ID は数字で入力してください");
        } catch (IllegalArgumentException e) {
            JOptionPane.showMessageDialog(this, e.getMessage());
        } catch (SQLException e) {
            JOptionPane.showMessageDialog(this, "データベースのエラー: " + e.getMessage());
        }
    }

    private void showList() {
        model.setRowCount(0);
        try {
            for (ProductDTO p : service.findAll()) {             // 図1 findAll()
                Object[] row = {p.getId(), p.getName(), p.getPrice(), p.getStock()};
                model.addRow(row);
            }
        } catch (SQLException e) {
            JOptionPane.showMessageDialog(this, "データベースのエラー: " + e.getMessage());
        }
    }
}

ProductService.java　入力の検査

package lesson17;

import java.sql.SQLException;
import java.util.List;

public class ProductService {
    private ProductDAO dao = new ProductDAO();

    public List<ProductDTO> findAll() throws SQLException {
        return dao.findAll();
    }

    public void add(ProductDTO p) throws SQLException {
        check(p);
        dao.insert(p);
    }

    public void update(ProductDTO p) throws SQLException {
        check(p);
        if (dao.update(p) == 0) {
            throw new IllegalArgumentException("ID " + p.getId() + " の商品はありません");
        }
    }

    public void delete(int id) throws SQLException {
        if (dao.delete(id) == 0) {
            throw new IllegalArgumentException("ID " + id + " の商品はありません");
        }
    }

    private void check(ProductDTO p) {
        if (p.getName() == null || p.getName().isBlank()) {
            throw new IllegalArgumentException("商品名を入力してください");
        }
        if (p.getPrice() < 0) {
            throw new IllegalArgumentException("価格に負の値は設定できません");
        }
        if (p.getStock() < 0) {
            throw new IllegalArgumentException("在庫に負の値は設定できません");
        }
    }
}

ProductDAO.java　データの出し入れ

package lesson17;

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.util.ArrayList;
import java.util.List;

public class ProductDAO {
    private static final String URL = "jdbc:mysql://localhost:3306/stock";
    private static final String USER = "root";
    private static final String PASSWORD = "password";

    // 全部の商品を読む（第11回と同じ）
    public List<ProductDTO> findAll() throws SQLException {
        List<ProductDTO> list = new ArrayList<>();
        String sql = "SELECT id, name, price, stock FROM products ORDER BY id";
        try (Connection con = DriverManager.getConnection(URL, USER, PASSWORD);
             PreparedStatement ps = con.prepareStatement(sql);
             ResultSet rs = ps.executeQuery()) {
            while (rs.next()) {
                list.add(new ProductDTO(rs.getInt("id"), rs.getString("name"),
                                        rs.getInt("price"), rs.getInt("stock")));
            }
        }
        return list;
    }

    // ID で1つ探す。無ければ null を返す
    public ProductDTO findById(int id) throws SQLException {
        String sql = "SELECT id, name, price, stock FROM products WHERE id = ?";
        try (Connection con = DriverManager.getConnection(URL, USER, PASSWORD);
             PreparedStatement ps = con.prepareStatement(sql)) {
            ps.setInt(1, id);
            try (ResultSet rs = ps.executeQuery()) {
                if (rs.next()) {
                    return new ProductDTO(rs.getInt("id"), rs.getString("name"),
                                          rs.getInt("price"), rs.getInt("stock"));
                }
            }
        }
        return null;
    }

    // 追加する。変わった行数を返す
    public int insert(ProductDTO p) throws SQLException {
        String sql = "INSERT INTO products (name, price, stock) VALUES (?, ?, ?)";
        try (Connection con = DriverManager.getConnection(URL, USER, PASSWORD);
             PreparedStatement ps = con.prepareStatement(sql)) {
            ps.setString(1, p.getName());
            ps.setInt(2, p.getPrice());
            ps.setInt(3, p.getStock());
            return ps.executeUpdate();
        }
    }

    // 更新する。変わった行数を返す
    public int update(ProductDTO p) throws SQLException {
        String sql = "UPDATE products SET name = ?, price = ?, stock = ? WHERE id = ?";
        try (Connection con = DriverManager.getConnection(URL, USER, PASSWORD);
             PreparedStatement ps = con.prepareStatement(sql)) {
            ps.setString(1, p.getName());
            ps.setInt(2, p.getPrice());
            ps.setInt(3, p.getStock());
            ps.setInt(4, p.getId());
            return ps.executeUpdate();
        }
    }

    // 削除する。変わった行数を返す
    public int delete(int id) throws SQLException {
        String sql = "DELETE FROM products WHERE id = ?";
        try (Connection con = DriverManager.getConnection(URL, USER, PASSWORD);
             PreparedStatement ps = con.prepareStatement(sql)) {
            ps.setInt(1, id);
            return ps.executeUpdate();
        }
    }
}

シーケンス図で使う記号と書き方

シーケンス図は、登場するオブジェクトのやりとりを上から下の時間順に描く。左上の sd は図の名前。

sd とライフライン

この部分のコード・詳しい説明を見る
記号・書き方名前意味と書き方
枠（sd）図の全体を囲み、左上に sd と流れの名前を書きます。設計書では枠を省いた図も多くあります。ほかの図から ref で呼ぶときは、この名前を使います。
ヘッダーとライフライン上に並ぶ四角がヘッダーで、「:クラス名」と書きます。下へ伸びる破線がライフラインです。上にある矢印ほど先に起きます。データベースや外部のシステムも、「:MySQL」「«system» 決済」のようにヘッダーにして、右の端に置きます。
アクター操作する人です。ユースケース図と同じ名前にします。
実行仕様ライフラインの上の細長い四角です。メソッドが動いている間を表します。
同期メッセージメソッドの呼び出しです。実線と黒塗りの矢じりで描き、線の上にメソッド名と引数を書きます。
戻りメッセージreturn で値を返す所です。破線と開いた矢じりで描き、線の上に返す値を書きます。設計書では戻りを省き、呼び出しの矢印に list = findAll() とまとめて書くことが多くあります。
非同期メッセージ返事を待たずに先へ進む呼び出しです。実線と開いた矢じりで描きます。
自己メッセージ自分のメソッドを呼ぶ所です。自分のライフラインへ戻る矢印で描きます。
alt複合フラグメントの1つで、どれか1つの段だけが起きます。Java の if・else です。段は破線で区切り、各段の頭に [ ] で条件（ガード条件）を書きます。最後の段は [else] です。
opt条件を満たすときだけ起きます。else の無い if です。
loop条件を満たす間、くり返します。Java の while・for です。
break条件を満たしたら、その枠の処理をして、囲んでいる処理を抜けます。Java の break・return や、例外を投げる所に当たります。
ref別のシーケンス図を呼ぶ枠です。中に呼ぶ図の名前を書きます。長い流れを、図を分けて描くときに使います。
[在庫あり] sell()条件付きメッセージメッセージの前に [ ] で条件を書いた形です。古い書き方ですが、設計書でよく見かけます。描くときは opt を使います。
生成new でインスタンスを作る所です。«create» と書いた破線の矢印で描き、作られた側のヘッダーは、その高さに描きます。
破棄ライフラインの終わりの大きな × です。そのインスタンスが無くなることを表します。接続を閉じる、セッションを消す、などで描きます。

1　枠・ヘッダー・ライフライン（①②③）

全体の枠には名前を書き、ヘッダーは参加者、縦の破線は参加者の存在を表す。

枠 → ヘッダー → ライフライン

この部分のコード・詳しい説明を見る

抜き出したのは、図1「商品を一覧する」の全体です。

① 全体を囲む枠と、左上の sd 商品を一覧する

①は、全体を囲む枠と、左上の sd 商品を一覧する です。この図が、何の流れを描いたものかを表します。sd は、シーケンス図（sequence diagram）の頭文字です。1つの流れ（シナリオ）を、1枚に描きます。名前を第15回のユースケース名とそろえると、どの流れの図かがすぐ分かります。

② :ProductFrame などの四角（ヘッダー）

②の :ProductFrame などの四角を、ヘッダーと言います。ヘッダーは、この流れに登場するインスタンスです。左から、画面・Service・DAO・MySQL の4つが並んでいます。

書き方は「: クラス名」です。並ぶのはクラスではなく、new で作った実物です。だから、コロンを付けて「この型の実物」と表します。区別が要るときは、コロンの前に名前を書きます（dao:ProductDAO）。

:MySQL はクラスではありませんが、DAO が SQL を送る相手なので並べています。

③ ヘッダーから下へ伸びる縦の破線（ライフライン）

③の、ヘッダーから下へ伸びる縦の破線がライフラインです。ライフラインは、そのインスタンスがいる間を表します。

上から下へ、時間が流れます。上にある矢印ほど先に起きます。横の並び順は、時間と関係ありません。矢印の上下を入れ替えると、コードの行の順番を入れ替えたことになります。

横の矢印と細長い四角は、次の④〜⑥で説明します。

よくある間違い：呼び出しの順番を入れ替える。図2「商品を登録する」で、一覧を読み直す findAll() を、登録の add(p) より上に描いた形です。下の図は、それを3つのインスタンスだけで描いたものです。上から順に読んでみてください。

間違いを含んだ図　一覧を読んでから登録している

上の4本の矢印では、画面が findAll() を呼び、DAO から List が戻っています。下の4本では、画面が add(p) を呼び、Service が DAO の insert(p) を呼んでいます。DAO が返す 1 は、追加できた行の数です。

上から読むと、一覧を読んでから登録しています。この順でコードを書くと、登録する前の一覧が画面に出ます。足した商品は表示されません。エラーにならないので、動かしただけでは気づきにくい間違いです。図にすると、矢印の上下で気づけます。描き始める前に、コードを上から指でたどってください。service. や dao. が出てくる順に番号を振っておくと、防げます。

2　実行仕様と、呼び出し・戻り（④⑤⑥）

細い縦長の四角は実行中、実線の矢印は呼び出し、破線の矢印は戻り値を示す。

呼び出し → 実行 → 戻り

この部分のコード・詳しい説明を見る

ProductFrame.java から抜き出しています。図1は、この行から始まります。

    private void showList() {
        // （中略）
            for (ProductDTO p : service.findAll()) {             // 図1 findAll()
            // （中略）
    }

showList は、一覧を表示し直すメソッドです。private なので、ProductFrame の中からだけ呼ばれます。1つ目の（中略）には、表を空にする行と、try の行があります。for は、service.findAll() が返した商品を、1件ずつ取り出す繰り返しです。この service.findAll() が、図1の最初の矢印 findAll() です。2つ目の（中略）には、取り出した商品を、画面の表に1行ずつ足す処理があります。

④ ライフラインの上の細長い四角（実行仕様）

④の、ライフラインの上の細長い四角が実行仕様です。実行仕様は、メソッドが動いている間を表します。呼ばれた所で始まり、戻す所で終わります。ProductService の四角の途中で、ProductDAO の四角が始まっています。DAO が終わるまで、Service が待っている、という意味です。ProductFrame の四角がいちばん長いのは、最初に呼び、最後に受け取るからです。

⑤ 実線と黒塗りの矢じりの矢印（同期メッセージ）

⑤の、実線と黒塗りの矢じりの矢印が同期メッセージです。同期メッセージは、メソッドの呼び出しを表します。線の上に、メソッド名と引数を書きます。Java のふつうのメソッド呼び出しは、返ってくるまで次の行へ進みません。だから「同期」です。service. や dao. で始まる呼び出しが、この矢印になります。

図1では、画面が Service の findAll() を呼び、続けて Service が DAO の findAll() を呼びます。DAO から MySQL への SELECT文 は、DAO が SQL の SELECT 文を送る所です。

⑥ 破線と開いた矢じりの矢印（戻りメッセージ）

⑥の、破線と開いた矢じりの矢印が戻りメッセージです。呼ばれた側が、return で値を返す所です。線の上に、返す値を書きます。

MySQL から DAO への 3行 は、表の3件の行が返ってくる所です。DAO から Service、Service から画面への List は、商品の一覧が入った List<ProductDTO> です。

なぜ描くのか。戻りが無いと、ProductFrame が何を受け取ったのかが読めないからです。List<ProductDTO> list = service.findAll(); の左側が書けません。UML では、戻りを省いてもよいことになっています。この講座では、何も返さない void のメソッド以外は、戻りも描きます。

よくある間違い：呼ぶ矢印と返す矢印の線を取り違える。下の図は、図1の画面・Service・DAO のやりとりを、線を逆にして描いたものです。

間違いを含んだ図　線と矢じりが逆

findAll() の矢印が破線、List の矢印が実線と黒塗りになっています。これでは「findAll() という値が返ってきて、List というメソッドを呼んだ」と読めてしまいます。線の種類は、矢印の向きより先に目に入ります。頼むのは実線＋黒塗り、返すのは破線です。

メッセージは3種類。線と矢じりで見分ける

上の図は、メッセージの3種類を並べたものです。1行目の同期と、3行目の戻りは、図1で見たものです。2行目の非同期メッセージは、返事を待たずに先へ進む呼び出しです。実線と開いた矢じりで描きます。send() は、説明のための例の名前です。非同期メッセージは、この講座のアプリには出てきません。戻りとの違いは、線が実線か破線かです。

アクターと自己メッセージ

⑦ 棒人間の 担当者（アクター）

⑦の棒人間の 担当者 はアクターです。システムの外から操作する人です。第15回のユースケース図と同じ名前にします。担当者からも、下へライフラインが伸びています。

追加を押す の矢印は、担当者が［追加］ボタンを押す所です。この矢印で、ProductFrame の実行仕様が始まります。誰の操作で流れが始まるかを示すために描きます。ユースケース記述の「担当者は、〜」の行が、アクターから出る矢印になります。

続く add(p) は、画面が Service の add を呼ぶ所です。p は、入力した値を入れた ProductDTO です。コードでは、service.add(new ProductDTO(0, name, price, stock)); の行です。最初の 0 は、ID の仮の値です。ID は、データベースが自動で振ります。右端の :ProductDAO は、この部分ではまだ呼ばれていません。

⑧ 自分に戻る矢印 check(p)（自己メッセージ）

⑧の、自分に戻る矢印 check(p) が自己メッセージです。自己メッセージは、同じインスタンスの、別のメソッドを呼ぶ形です。add の中で、同じ ProductService の check を呼んでいます。check は、商品名・価格・在庫を検査するメソッドです。重ねて描いた小さな四角が、check が動いている間です。

図2の下のほうの showList() も、同じ自己メッセージです。1つのクラスの中の大事な手順を見せるために描きます。private メソッドの呼び出しは、たいていこの形になります。

よくある間違い：getter まで全部描く。コードの呼び出しを、1つ残らず矢印にした形です。

間違いを含んだ図　getter まで全部描いた

Service は、DTO の getName()・getPrice()・getStock() を順に呼んでいます。戻りの "付箋"・200・25 は、登録しようとしている商品名・価格・在庫です。そのあと DAO の insert(p) を呼び、DAO もまた DTO の getter を呼んでいます。右下の「…まだ続く」は、このあとも矢印が続くという意味です。

矢印が多すぎて、「検査して、登録する」という流れが埋もれてしまいます。描くのは、まず層をまたぐ呼び出し（画面 → Service → DAO）です。層は、第13回で分けた画面・Service・DAO の3つの受け持ちです。もう1つは、流れの分かれ目になる手順（check(p) のような検査）です。写した図2が、その形です。

4　alt とガード条件（⑨⑩）

alt は if / else のような条件分岐。各段に [条件] を書いて、どれを実行するか示す。

alt [条件]

この部分のコード・詳しい説明を見る

⑨ alt と書いた枠（複合フラグメント）

⑨の、alt と書いた枠が複合フラグメントです。複合フラグメントは、図の一部を囲んで、特別な動きを示す枠です。

alt は、条件で道が分かれる所です。Java の if / else if / else に当たります。枠は、横の破線で3つの段に区切ってあります。当てはまった段の矢印だけが起きます。うまくいかない道（第15回の代替フロー）も、1枚に描くために使います。

⑩ 角括弧で書いた条件（ガード条件）

⑩の、角括弧で書いた条件がガード条件です。その段の道に入る条件です。

1段目の [商品名が空] は、商品名が入力されていないときです。このとき Service は、IllegalArgumentException を投げて、画面へ戻ります。IllegalArgumentException は、渡された値がおかしいことを表す例外です（第9回）。例外で戻るときも破線で描き、線の上に例外の名前を書きます（この講座の決まり）。

画面から担当者への 理由を表示 は、例外の理由を担当者に見せる所です。コードでは、catch で受け止めた例外の e.getMessage() を表示する行です。

2段目の [価格か在庫が負] は、価格か在庫に、0より小さい数が入ったときです。矢印は、1段目と同じです。

3段目の [else] は、上のどちらにも当てはまらないとき、つまり入力が正しいときです。このときだけ、Service が DAO の insert(p) を呼びます。DAO が返す 1 は、追加できた行の数です。check(p) が例外を投げた段では、insert を呼びません。それが図で分かります。

段は、分かれる道の数だけ作ります。上の2段は、どちらも例外で断る道ですが、段を分けています。確かめる中身が違うからです。商品名は入力されているか、価格と在庫は負でないかを確かめます。そこで、check の価格の if と在庫の if を、1段にまとめています。商品名の if とは、段を分けています。

よくある間違い：alt に条件を書かない。下の図は、図2の alt を、条件を書かずに描いたものです。

間違いを含んだ図　alt に条件が書いていない

5　loop と生成（⑪⑫）

loop は while や for のような繰り返し。繰り返す範囲と終了条件を表す。

loop [条件]

この部分のコード・詳しい説明を見る

抜き出したのは、図2の [else] の段の下の部分です。登録したあと、一覧を表示し直す所です。

⑪ loop の枠と [rs.next() が true]

左上の showList() は、画面の自己メッセージです（⑧と同じ形）。その中で、画面が Service の findAll() を呼び、続けて Service が DAO の findAll() を呼びます。

⑪の loop の枠は、繰り返しです。Java の while (rs.next()) に当たります。rs.next() は、読んだ結果に次の行があれば true を返すメソッドです。枠の中の [rs.next() が true] が、繰り返しを続ける条件です。

3行あれば、new ProductDTO(...) が3回動きます。でも、矢印を3本は描きません。1本を枠で囲んで、繰り返すことを示します。

⑫ «create» と書いた破線の矢印（生成）

⑫の、«create» と書いた破線の矢印が生成です。生成は、new でインスタンスを作る所です。

矢印の先の :ProductDTO のヘッダーは、ほかのヘッダーより下にあります。作られたものは、その高さにヘッダーを描き、そこからライフラインを始めます。最初からいるものと、途中で生まれたものを見分けるためです。loop の枠の中なので、3つ作られても、ヘッダーは1つで代表させます。

枠の下の2本の List の破線は、戻りメッセージです。作った ProductDTO を入れた一覧が、DAO から Service へ戻り、続けて画面へ戻ります。

クラスとインスタンス、コンストラクタ

第8章　設計図と実体 ／ フィールド ／ コンストラクタと this

今日の主役

クラス　インスタンス　フィールド　コンストラクタと this

今日できるようになること
  • クラスから new でインスタンスを作れる
  • 同じクラスから作った2つのインスタンスが、別物だと説明できる
  • コンストラクタで、作ると同時に値を入れられる
① 今日の主役

Java での意味

言葉意味
クラスオブジェクトの設計図。そのオブジェクトが持つ値（フィールド）と、できる処理（メソッド）をまとめて定義したものです。public class Product { ... }
インスタンスクラスをもとに new で作った実体。インスタンスごとに、別々のフィールドの値を持ちます。Product p1 = new Product("ボールペン", 150);
フィールドクラスの中、メソッドの外に書く変数です。インスタンスごとに、別々の値を持ちます。String name; int price;
コンストラクタと thisコンストラクタは、new したときに1回だけ動く、メソッドに似た、クラスと同じ名前の特別なものです（戻り値の型は書きません）。this は「このインスタンス自身」を指す言葉で、this.name はフィールドの name を表します。Product(String name, int price) { this.name = name; this.price = price; }

たとえで言うと

クラスは「たい焼きの型」、インスタンスは「たい焼き」

型そのものは食べられません。型から焼いたものを食べます。

クラスは「たい焼きの型」、インスタンスは「たい焼き」

ここでの「型」は、たい焼きを焼く焼き型のことです。Java の型（int など）とは別の意味です。

たい焼きの型は1つあれば足ります。そこから何匹でも焼けます。あんこ入りとクリーム入りは、別々のたい焼きです。

Java も同じです。Product というクラスを1つ書けば、new するたびに別々の商品（インスタンス）が作られます。p1 の名前を変えても、p2 には影響しません。

型（クラス）そのものには、あんこは入っていません。new を書かずに値を入れようとしてエラーになるのは、これが理由です。

フィールドは「くぼみ」、コンストラクタは「焼くときの手順」、this は「いま焼いているこの1匹」

焼き型には、あんこを入れるくぼみがあります。どのたい焼きにも同じくぼみがあり、中身だけが1匹ごとに違います。このくぼみがフィールドです。

焼くときは、生地を流してあんこを詰める手順が決まっています。この「焼くときの手順」がコンストラクタです。手順の中で「いま焼いているこの1匹に詰める」と指すのが this です。

なぜ必要か

クラス名前・価格・在庫のように1つの物に付いた値を、ばらばらの変数ではなく、ひとまとまりで扱うためです。
インスタンス1つの設計図から、値の違う物をいくつでも作るためです。
フィールド1つ1つのインスタンスが、自分の値（名前・価格など）を持ち続けるためです。
コンストラクタと this作ると同時に値を入れれば、入れ忘れを防げるからです。this が無いと、同じ名前の引数とフィールドを区別できません。

今日のゴールは、この絵をコードで書けるようになることです。まず写します。

全体像

プロジェクトの中は、次の2つのファイルだけです。import などを書き足す必要はありません。同じパッケージに置いたクラスどうしは、名前だけで使えます。

どちらも1行目は package lesson04; です。手順⑤で作ったパッケージ lesson04 の中にある、という意味で、Eclipse がクラスを作ったときに書く1行と同じです。消すと「Unresolved compilation problem」で動かなくなります。

下の2つが、それぞれのファイルの中身の全部です。行の右にある ①〜⑥ は、③解説の番号です。

プロジェクトの中身。この2つのファイルで全部です

Product.java　設計図のほう

package lesson04;

public class Product {
    String name;                          // ① フィールド
    int price;                            // ① フィールド

    Product(String name, int price) {     // ② コンストラクタ
        this.name = name;                 // ③ this
        this.price = price;               // ③ this
    }

    void show() {                         // ④ メソッド
        System.out.println(name + " / " + price + "円");
    }
}

Main.java　使うほう

package lesson04;

public class Main {
    public static void main(String[] args) {
        Product p1 = new Product("ボールペン", 150);   // ⑤ new
        Product p2 = new Product("ノート", 220);       // ⑤ new

        p1.show();                                     // ⑥ 呼び出し
        p2.show();                                     // ⑥ 呼び出し
    }
}

期待される実行結果

ボールペン / 150円 ノート / 220円

実行するのは Main のほうです。Product には main が無いので、Product を選んで実行しても動きません。

③ 解説

写したコードを、行の右の番号の順に説明します。説明する所のコードを、それぞれの頭に抜き出しています。よくある間違いも一緒に見ます。

1　フィールド（①）

Product.java（抜き出し）

    String name;                          // ① フィールド
    int price;                            // ① フィールド

String name; と int price; はフィールドです。クラスの直下に書いた変数で、たとえの「あんこを入れるくぼみ」です。なぜフィールドにするのか。商品ごとに名前と価格を持たせるためです。インスタンス1つ1つが、自分の name と price を持ちます。

2　コンストラクタと this（②③）

Product.java（抜き出し）

    Product(String name, int price) {     // ② コンストラクタ
        this.name = name;                 // ③ this
        this.price = price;               // ③ this
    }

Product(String name, int price) { ... } はコンストラクタです。new したときに1回だけ自動で動きます。名前はクラスと同じにし、戻り値の型（void など）を書きません。なぜコンストラクタを書くのか。作った時点で名前と価格を入れるためです。あとから1つずつ入れる書き方だと、入れ忘れが起きます。

this は「いま作っているこのインスタンスの」という意味です。左の this.name はフィールド、右の name は受け取った引数です。なぜ this. を付けるのか。引数とフィールドが同じ名前だからです。同じものを表しているので同じ名前が自然ですが、そのままでは Java は近いほう（引数）を選びます。this. で「この実物の欄」と指します。

よくある間違い：this. を付け忘れる。エラーにはならず、コンパイルは通ります。実行すると null / 0円 と出ます。Main は写したままです。

Product.java（間違いあり）

package lesson04;

public class Product {
    String name;
    int price;

    Product(String name, int price) {
        name = name;                      // ここが問題
        price = price;                    // ここが問題
    }

    void show() {
        System.out.println(name + " / " + price + "円");
    }
}

実行結果

null / 0円 null / 0円

this は「この実物の」という指さし

name = name; は、引数に引数を入れているだけです。フィールドには何も入らず、初期値のまま残ります。写したコードのとおり this. を付ければ、正しく表示されます。

ここで出た言葉null　「何も入っていない」を表す値。String のフィールドに何も入れないと、これになります初期値　フィールドに最初から入っている値。String は null、int は 0
Eclipse では name = name; の行に黄色い警告「変数 name への代入は無効です」が出ます。赤ではないので見落としやすく、いちばん多い詰まり方です。null / 0円 を見たら、まず this. を疑ってください。

よくある間違い：引数なしで new する。名前と価格を受け取るコンストラクタがあるのに、引数なしで new した形です。

Main.java（間違いあり）

package lesson04;

public class Main {
    public static void main(String[] args) {
        Product p1 = new Product();      // エラー
        p1.name = "ボールペン";
        p1.price = 150;

        p1.show();
    }
}

エラーメッセージ（Eclipse）

コンストラクター Product() は未定義です （The constructor Product() is undefined）

コンストラクタを1つも書かないときは、Java が引数なしのものを黙って用意しています。自分で書いた瞬間に、その気づかいは無くなります。写したコードのとおり、new Product("ボールペン", 150) と値を渡して作ります。

3　インスタンスを作って、メソッドを呼ぶ（④⑤⑥）

Product.java（抜き出し）

    void show() {                         // ④ メソッド
        System.out.println(name + " / " + price + "円");
    }

void show() { ... } はメソッドです。static が付いていないので、インスタンスに対して呼びます。なぜメソッドにするのか。表示のしかたを1か所にまとめるためです。中の name と price は、呼ばれたインスタンスのものが使われます。

Main.java（抜き出し）

    public static void main(String[] args) {
        Product p1 = new Product("ボールペン", 150);   // ⑤ new
        Product p2 = new Product("ノート", 220);       // ⑤ new

        p1.show();                                     // ⑥ 呼び出し
        p2.show();                                     // ⑥ 呼び出し
    }

new Product("ボールペン", 150) で、インスタンスを1つ作ります。たい焼きを1匹焼く操作です。丸括弧の中の値が、コンストラクタに渡ります。Product p1 = … の左の Product は、変数 p1 の型です（int stock の int と同じ位置）。商品を増やすときは new の行を足すだけで、Product は1行も変えません。

p1.show(); は、ドットで「p1 の show」を呼びます。なぜ p1. を付けるのか。どの商品を表示するかを指定するためです。p1 なら「ボールペン」、p2 なら「ノート」が表示されます。

よくある間違い：new を書かずに使う。たい焼きの型に、直接あんこを詰めようとした形です。Product は写したままです。

Main.java（間違いあり）

package lesson04;

public class Main {
    public static void main(String[] args) {
        Product.name = "ボールペン";      // エラー
        Product.price = 150;              // エラー

        System.out.println(Product.name + " / " + Product.price + "円");
    }
}

エラーメッセージ（Eclipse）

非 static フィールド Product.name を static 参照できません （Cannot make a static reference to the non-static field Product.name）

設計図そのものに、名前や価格は書き込めない

Product は設計図です。設計図には「名前という欄がある」と決めてあるだけで、値を入れる箱はまだどこにもありません。箱は new で実物を作ったときに、実物1つにつき1組できます。写したコードのとおり、new で作ってから p1.show() と呼びます。エラー文の「static」は次回扱います。

④ 自力で書く　1　Book

Book.java

package lesson04;

public class Book {
    String title;
    String author;
    int price;

    // ここにコンストラクタを書く
    Book(String title, String author, int price) {
        this.title = title;
        this.author = author;
        this.price = price;
    }

    void show() {
        // ここに「『題名』著者 / 価格円」の表示を書く
        System.out.println("『" + title + "』" + author + " / " + price + "円");
    }
}

BookMain.java

package lesson04;

public class BookMain {
    public static void main(String[] args) {
        Book[] books = {
            // ここに new Book(...) を3冊分、カンマで区切って書く
            new Book("吾輩は猫である", "夏目漱石", 800),
            new Book("こころ", "夏目漱石", 600),
            new Book("走れメロス", "太宰治", 500)
        };

        // ここに拡張for文を書き、1冊ずつ show() を呼ぶ
        for (Book b : books) {
            b.show();
        }
    }
}

実行結果

『吾輩は猫である』夏目漱石 / 800円 『こころ』夏目漱石 / 600円 『走れメロス』太宰治 / 500円

null・例外と try-catch

第11章 11-4 と 第12章　null ／ 例外と try-catch ／ 入力の検査

今日の主役

null　例外　try-catch

今日できるようになること
  • 例外が起きると、その行から先が実行されないことを説明できる
  • try-catch で例外を受け止め、プログラムを続けられる
  • null かどうかを == で確かめてから使える
① 今日の主役

Java での意味

言葉意味
null参照型の変数が「何も指していない」ことを表す値です。null の変数でメソッドを呼ぶと NullPointerException になります。Product found = null; found.show(); // NullPointerException
例外プログラムの実行中に起きた、処理を続けられない事態。また、それを表すオブジェクトのこと。例外が起きると処理はそこで止まり、呼び出した側へ伝わります。try-catch で受け止めれば処理を続けられ、どこでも受け止めなければプログラムが止まります。throw new IllegalArgumentException("..."); try { ... } catch (NumberFormatException e) { ... }
try-catch例外が起きるかもしれない処理を try { } で囲み、起きたときの処理を catch { } に書く文です。finally { } は、成功しても失敗しても最後に必ず動きます。try { int n = Integer.parseInt(text); } catch (NumberFormatException e) { System.out.println("数字で入力してください"); }

たとえで言うと

例外は「投げられるボール」、catch は「グローブ」

受け止める人がいれば、試合は続きます。誰もいなければ、そこで試合が止まります。

例外は「投げられるボール」。catch が受け止めなければ、そこで止まる

メソッドの中で「これ以上は続けられない」事態が起きることがあります。在庫に -5 を入れようとした、数字のはずの入力が「abc」だった、などです。そのとき Java は、その場で例外というボールを投げます。

ボールは、そのメソッドを呼んだ側へ飛んでいきます。呼んだ側が catch というグローブを構えていれば、受け止めてその先へ進めます。

誰も受け止めなければ、プログラムはそこで止まります。コンソールに出る赤い文字は、ボールがどこから飛んできたかの記録です。

構える範囲が try、捕るのが catch。誰もいない所が null

ボールを捕るには、飛んでくる間グローブを構えておきます。構えている範囲が try、捕って対応するのが catch です（try-catch）。

守備位置に、誰もいないこともあります。選手がいない状態が null です。誰もいない守備位置に「捕って」と指示を出す（メソッドを呼ぶ）と、NullPointerException になります。

なぜ必要か

null「見つからなかった」「まだ作っていない」を、はっきり表すためです。
例外続けられない事態が起きたことを、呼んだ側に確実に伝えて、対処させるためです。
try-catch例外が起きてもプログラムを止めずに、代わりの処理をするためです。

今日のゴールは、ボールを投げる側と受け止める側を、両方書けるようになることです。まず写します。

package lesson09;

public class Product {
    private static int count = 0;   // 作った商品の数（全体で1つ）

    private int id;
    private String name;
    private int price;
    private int stock;

    public Product(int id, String name, int price, int stock) {
        this.id = id;
        this.name = name;
        this.price = price;
        this.stock = stock;
        count++;
    }

    public int getId() { return id; }
    public String getName() { return name; }
    public int getPrice() { return price; }
    public int getStock() { return stock; }

    public void setPrice(int price) {
        if (price < 0) {
            System.out.println("価格に負の値は設定できません");
            return;
        }
        this.price = price;
    }

    public void setStock(int stock) {
        if (stock < 0) {
            throw new IllegalArgumentException("在庫に負の値は設定できません");  // ① throw
        }
        this.stock = stock;
    }

    public void show() {
        System.out.println(id + " / " + name + " / " + price + "円 / 残り" + stock + "個");
    }

    public static int getCount() { return count; }
}

Main.java　使うほう

package lesson09;

import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

public class Main {
    public static void main(String[] args) {
        List<Product> products = new ArrayList<>();
        products.add(new Product(1, "ボールペン", 150, 30));
        products.add(new Product(2, "ノート", 220, 10));
        products.add(new Product(3, "消しゴム", 100, 50));

        Product note = products.get(1);                               // 1番目（0から数える）の「ノート」

        try {                                                         // ② try
            note.setStock(-5);                                        // ③ ここで例外が起きる
            System.out.println("在庫を変えました");                   // ③ 飛ばされる
        } catch (IllegalArgumentException e) {                        // ④ catch
            System.out.println("変えられません: " + e.getMessage());  // ⑤ getMessage
        } finally {                                                   // ⑥ finally
            note.show();
        }

        Map<Integer, Product> byId = new HashMap<>();
        for (Product p : products) {
            byId.put(p.getId(), p);
        }
        Product found = byId.get(9);                        // ⑦ 無い名札なら null
        if (found == null) {                                // ⑧ null か確かめる
            System.out.println("ID 9 の商品はありません");
        } else {
            found.show();
        }

        System.out.println("処理を続けます");
    }
}

③ 解説

写したコードを、行の右の番号の順に説明します。説明する所のコードを、それぞれの頭に抜き出しています。よくある間違いも一緒に見ます。

1　例外を投げる（①）

Product.java（抜き出し）

public void setStock(int stock) {
    if (stock < 0) {
        throw new IllegalArgumentException("在庫に負の値は設定できません");  // ① throw
    }
    this.stock = stock;
}

throw は「ここで例外を投げる」命令です。IllegalArgumentException は「渡された値がおかしい」ことを表す例外で、丸括弧の中が理由の文になります。throw の行でメソッドは終わるので、this.stock = stock; まで届きません。

もし setStock が表示して return するだけなら、Main は失敗に気づかず、次の行へ進んでしまいます。throw してあるので、Main は受け止めるか止まるかのどちらかになり、失敗を見逃しません。

2　try で囲む（②③）

Main.java（抜き出し）

public static void main(String[] args) {
    // （中略）
    try {                                               // ② try
        note.setStock(-5);                              // ③ ここで例外が起きる
        System.out.println("在庫を変えました");         // ③ 飛ばされる
    // （中略）
}

try は、例外が起きるかもしれない処理を囲みます。グローブを構える範囲です。try の外で起きた例外は受け止めません。

note.setStock(-5); で例外が起きると、try の残りの「在庫を変えました」は飛ばされ、catch へ移ります。例外が起きた行から下は実行されません。失敗したのに「在庫を変えました」と表示しないで済むのは、このためです。-5 を 25 に変えると例外は起きず、「在庫を変えました」が表示されて、catch は動きません。

よくある間違い：try で囲まずに呼ぶ。②〜⑥を消して、note.setStock(-5); をそのまま呼んだ形です。Product は写したままです。

3　catch で受け止め、finally で締める（④⑤⑥）

Main.java（抜き出し）

public static void main(String[] args) {
    // （中略）
    } catch (IllegalArgumentException e) {                        // ④ catch
        System.out.println("変えられません: " + e.getMessage());  // ⑤ getMessage
    } finally {                                                   // ⑥ finally
        note.show();
    }
    // （中略）
}

catch は、丸括弧に書いた種類の例外が来たときだけ動きます。e は届いた例外そのものです。受け止めたあとの対応をここに書くので、プログラムは止まらずに先へ進めます。

e.getMessage() は、例外に入っている理由の文を取り出します。Product で書いた「在庫に負の値は設定できません」が出てきます。理由は、投げた側（Product）がいちばんよく知っています。

finally の中は、例外が起きても起きなくても、最後に必ず実行されます。なぜ finally に書くのか。成功でも失敗でもやる後片付け（ここでは今の在庫の表示）を、1か所に書くためです。try と catch の両方に同じ行を書かずに済みます。

よくある間違い：catch の中を空にする。止まらないようにしたつもりで、⑤の行を消した形です。Product は写したままです。

NullPointerException が起きるのは、ほぼ次の3つの型です。今日の⑦は①の型です。

型例
① 探したが無かったMap の get に無い名札を渡すと null が返る

nullと例外

obj が null のまま obj.toString() を呼ぶとどうなる？

答えと理由を見る

NullPointerExceptionが発生する。使用前に null の可能性を確認する。catchは原因を自動で修正するわけではない。

④ 自力で書く

ここからは自力です。2問あります。①で「変えられません」が表示できたら、今日の目的は達成です。

②で使う道具。キーボードから入力を受け取るには Scanner を使います（import java.util.Scanner;）。sc.nextLine() で1行読み、読んだものは文字列です。Integer.parseInt(文字列) で数字にします。"25" は 25 になり、"abc" は数字にできないので NumberFormatException を投げます。

catch は続けて何個も書けます。上から順に調べ、当てはまった1つだけが動きます。NumberFormatException は IllegalArgumentException の子クラス（第6回の継承）なので、両方書くときは子を先に書きます。逆にすると「NumberFormatException の到達不可能な catch ブロック。すでに IllegalArgumentException の catch ブロックによって処理されています」というコンパイルエラーになります。

課題

  • ①　Product の setPrice を、負の値なら IllegalArgumentException を投げる形に書き換える。PriceMain で -100 と 180 を順に設定し、例外は catch して理由を表示する。
  • ②　StockInput で、正しい在庫数が入るまで聞き直す。数字でないときと、負の値のときは、それぞれ知らせてもう一度聞く。うまく設定できたら、ループを抜けて商品を表示する。

3つのファイルの全体です。// ここに… の所を書きます。Product は②の Product.java を書き換えます。

package lesson09;

public class Product {
    private static int count = 0;   // 作った商品の数（全体で1つ）

    private int id;
    private String name;
    private int price;
    private int stock;

    public Product(int id, String name, int price, int stock) {
        this.id = id;
        this.name = name;
        this.price = price;
        this.stock = stock;
        count++;
    }

    public int getId() { return id; }
    public String getName() { return name; }
    public int getPrice() { return price; }
    public int getStock() { return stock; }

    public void setPrice(int price) {
        // ここに、price が負の値なら IllegalArgumentException を投げる処理を書く
        if (price < 0) {
            throw new IllegalArgumentException("価格に負の値は設定できません");
        }
        this.price = price;
    }

    public void setStock(int stock) {
        if (stock < 0) {
            throw new IllegalArgumentException("在庫に負の値は設定できません");
        }
        this.stock = stock;
    }

    public void show() {
        System.out.println(id + " / " + name + " / " + price + "円 / 残り" + stock + "個");
    }

    public static int getCount() { return count; }
}

④ 自力で書く　2　正しい数字が入るまで聞き直す

StockInput.java

package lesson09;

import java.util.Scanner;

public class StockInput {
    public static void main(String[] args) {
        Product note = new Product(2, "ノート", 220, 10);
        Scanner sc = new Scanner(System.in);

        while (true) {
            System.out.println("在庫数を入力してください");
            String input = sc.nextLine();

            // ここに try-catch を書く
            try {
                note.setStock(Integer.parseInt(input));
                break;
            } catch (NumberFormatException e) {
                System.out.println("数字で入力してください: " + input);
            } catch (IllegalArgumentException e) {
                System.out.println("変えられません: " + e.getMessage());
            }
        }

        note.show();
        sc.close();
    }
}

実行結果

在庫数を入力してください 数字で入力してください: abc 在庫数を入力してください 変えられません: 在庫に負の値は設定できません 在庫数を入力してください 2 / ノート / 220円 / 残り25個
while (true) は、break するまで回り続けるループです。例外が起きると break; の行は飛ばされ、catch のあとにループの先頭へ戻ります。正しい値のときだけ break に届きます。

言葉読み方意味
例外れいがい続けられない事態が起きたときに、Java が投げる知らせ。受け止めないとプログラムが止まります
throwすろー「ここで例外を投げる」命令。throw new IllegalArgumentException("理由");
tryとらい例外が起きるかもしれない処理を囲む範囲
catchきゃっち丸括弧に書いた種類の例外が来たときに動く所。catch (NumberFormatException e)
finallyふぁいなりー例外が起きても起きなくても、最後に必ず動く所。後片付けを書きます
getMessage()げっとめっせーじ例外に入っている理由の文を取り出すメソッド
IllegalArgumentExceptionいりーがる あーぎゅめんと えくせぷしょん「渡された値がおかしい」ことを表す例外。自分で投げるときによく使います
NumberFormatExceptionなんばー ふぉーまっと えくせぷしょん文字列が数字の形になっていないことを表す例外。Integer.parseInt が投げます。IllegalArgumentException の子クラスです
NullPointerExceptionぬる ぽいんたー えくせぷしょんnull に対してメソッドを呼んだり、フィールドを使ったりしたときの例外
nullぬる「どの実物も指していない」ことを表す値。比べるときは == を使います
握りつぶしにぎりつぶし例外を catch して何もしないこと。失敗が誰にも伝わらなくなります
while (true)ほわいる とぅるー条件がいつも true なので、break するまで回り続けるループ
breakぶれーくループをその場で抜ける命令。ループの後ろの行へ進みます
Scannerすきゃなーキーボードからの入力を読む道具。nextLine() で1行読みます
Integer.parseIntいんてじゃー ぱーすいんと文字列を int に変えるメソッド。変えられないときは NumberFormatException を投げます
子クラスこくらすほかのクラスを継承したクラス（第6回）。catch では子を先に書きます

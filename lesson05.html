カプセル化と static

第9章　カプセル化 ／ static の意味 ／ static とインスタンスの使い分け

今日の主役

カプセル化　private　static

今日できるようになること
  • フィールドを private にして、getter と setter を通して読み書きできる
  • setter に検査を入れて、おかしな値をはじける
  • static が「クラスに1つ」、付けないと「実物1つにつき1つ」だと説明できる
ここで迷ったら

static・private・インスタンスの違いを詳しく読む →

コードの動きと間違えやすい点を別ページで確認できます。分かる場合は飛ばしてOK。

① 今日の主役

Java での意味

言葉意味
カプセル化フィールドを private で隠し、値の出し入れを public のメソッド（getter・setter）だけに限ることです。private int price; public int getPrice() { return price; } public void setPrice(int price) { ... }
privateアクセス修飾子の1つ。付けたフィールドやメソッドは、そのクラスの中からしか使えません。外からは public のメソッド（getter・setter）を通して扱います。private int price;
staticクラスそのものに属することを表す修飾子。static を付けたフィールドは、インスタンスがいくつあってもクラスに1つだけで、全部のインスタンスで共有されます。static メソッドは、インスタンスを作らずに「クラス名.メソッド名()」で呼べます。private static int count; Product.getCount()

たとえで言うと

private は「鍵のかかった棚」、static は「お店に1つのカウンター」

棚の中身は受付を通して変えます。カウンターは、商品がいくつあってもお店に1つです。

private は「鍵のかかった棚」。中身は受付（setter）を通して変える

フィールドに何も付けないと、Main から p1.price = -100; と書けてしまいます。マイナス100円の商品ができてしまいます。値を確かめるメソッドを作っても、それを通らずに直接書く道が残ります。

お店の棚に鍵をかけ、受付の人だけが開けられるようにします。受付の人は「マイナスの値札は付けられません」と断れます。Java では、鍵が private、受付が setter（値を入れるメソッド）です。

static は「お店に1つのカウンター」。商品がいくつあっても1つだけ

もう1つは、レジ横の「登録した商品の数」のカウンターです。商品が何個あっても、カウンターはお店に1つです。商品ごとに持つものではありません。Java では、これに static を付けます。

カプセル化は、鍵のかかった棚と受付をひとまとめにして、受付だけを開けておく仕組み

鍵のかかった棚と受付を組み合わせて、中身は受付を通さないとさわれないようにする。この仕組み全体をカプセル化と言います。

なぜ必要か

カプセル化値を変える道を1か所にまとめ、そこで正しい値かどうかを確かめられるようにするためです。
private外から直接おかしな値（マイナスの価格など）を入れられないようにするためです。
staticインスタンスごとではなく、全体で1つだけ持ちたい値や処理があるからです。

Product.java　設計図のほう

package lesson05;

public class Product {
    private static int count = 0;   // ① 作った商品の数（全体で1つ）

    private int id;                 // ② private
    private String name;            // ② private
    private int price;              // ② private
    private int stock;              // ② private

    public Product(int id, String name, int price, int stock) {
        this.id = id;
        this.name = name;
        this.price = price;
        this.stock = stock;
        count++;                    // ③ 作るたびに1増える
    }

    public int getId() { return id; }              // ④ getter
    public String getName() { return name; }       // ④ getter
    public int getPrice() { return price; }        // ④ getter
    public int getStock() { return stock; }        // ④ getter

    public void setPrice(int price) {              // ⑤ setter
        if (price < 0) {
            System.out.println("価格に負の値は設定できません");
            return;
        }
        this.price = price;
    }

    public void setStock(int stock) {              // ⑤ setter
        if (stock < 0) {
            System.out.println("在庫に負の値は設定できません");
            return;
        }
        this.stock = stock;
    }

    public void show() {
        System.out.println(id + " / " + name + " / " + price + "円 / 残り" + stock + "個");
    }

    public static int getCount() { return count; }   // ⑥ static メソッド
}

public class Main {

1　欄に private と static を付ける（①②）

Product.java から抜き出しています。

private static int count = 0;   // ① 作った商品の数（全体で1つ）

private int id;                 // ② private
private String name;            // ② private
private int price;              // ② private
private int stock;              // ② private

id name price stock には private が付いています。Product クラスの中からしか読み書きできない、という印です。たとえの「鍵のかかった棚」です。

このコードの欄はどれも private なので、Main で p1.price = -100; と書くとエラーになります。値を変える道は setter だけです。

count には static も付いています。商品ごとではなく、Product クラスに1つだけある欄です。たとえの「お店に1つのカウンター」です。

「作った商品の数」は、商品1つ1つではなく全体で1つの数なので、count に static を付けています。static が無いと商品ごとに別の count ができ、どれも1のままになります。

2　作るたびに数える（③）

public Product(int id, String name, int price, int stock) {
    this.id = id;
    this.name = name;
    this.price = price;
    this.stock = stock;
    count++;                    // ③ 作るたびに1増える
}

コンストラクタの中で、count を1増やします。なぜここで数えるのか。商品を作るときは必ずコンストラクタが動くので、ここで数えれば数え漏れがありません。商品をもう1つ new すれば、最後の数は3になります。

コンストラクタの中からでも、static の欄 count に届きます。コンストラクタに付けた public（どこからでも使える）は、別のパッケージからも new できるようにする印です。

3　読み書きの入口 getter と setter（④⑤）

public int getId() { return id; }              // ④ getter
public String getName() { return name; }       // ④ getter
public int getPrice() { return price; }        // ④ getter
public int getStock() { return stock; }        // ④ getter

public void setPrice(int price) {              // ⑤ setter
    if (price < 0) {
        System.out.println("価格に負の値は設定できません");
        return;
    }
    this.price = price;
}
// （中略）

getter は、フィールドの値を返すだけのメソッドです。なぜ要るのか。private にすると、外からは読むこともできなくなるからです。中身が return だけなので1行で書いていますが、{ } の中を改行して書いても同じ意味です。

setter は、フィールドに値を入れるメソッドです。負の値なら表示を出して return; で抜け、そうでなければ入れます。なぜ setter を通すのか。値を変える入口をここ1か所にすれば、検査もここ1か所で済むからです。setStock も同じ形です。

種類名前戻り値の型引数
getterget ＋ フィールド名（先頭を大文字）フィールドと同じ型なし
setterset ＋ フィールド名（先頭を大文字）voidフィールドと同じ型を1つ
Eclipse では、コードの何もない所で右クリック →［ソース］→［getter および setter の生成］で、getter と setter を自動で作れます。ただし、自動で作った setter に検査は入っていません。if (price < 0) のような検査は、自分で書き足します。

4　実物に対して呼ぶか、クラス名で呼ぶか（⑥⑦⑧）

public static int getCount() { return count; }   // ⑥ static メソッド

getCount() は static を付けたメソッドです。実物ではなく、クラスに対して呼びます。count はクラスに1つなので、どの商品に聞いても答えは同じだからです。

Main.java から抜き出しています。

public static void main(String[] args) {
    Product p1 = new Product(1, "ボールペン", 150, 30);
    Product p2 = new Product(2, "ノート", 220, 10);

    p1.setPrice(-100);                                                 // ⑦ 入口を通す
    p1.setPrice(180);                                                  // ⑦ 入口を通す
    // （中略）
    System.out.println("ノートの在庫: " + p2.getStock() + "個");       // ⑦ 入口を通す
    System.out.println("登録した商品: " + Product.getCount() + "個");  // ⑧ クラス名で呼ぶ
}

p1.setPrice(-100) と p2.getStock() は、実物（p1 p2）に対して入口のメソッドを呼んでいます。価格や在庫は商品ごとに違うので、どの商品のものかを指します。-100 ははじかれ、180 は通ります。

Product.getCount() は、クラス名にドットを付けて呼んでいます。static の付いたものはクラスに1つなので、実物を指さなくても呼べます。

よくある間違い：static の付かないメソッドを、クラス名で呼ぶ。Product は写したままです。

エラーメッセージ（Eclipse）

型 Product の非 static メソッド getName() を static 参照することはできません （Cannot make a static reference to the non-static method getName() from the type Product）

クラス名で呼べるのは、クラスに1つしかないもの（static）だけ

名前は商品ごとに違うので、クラス名で聞いても「どの商品の名前か」が決まりません。p1.getName() のように実物を指します。static の付いたメソッドの中からも、static の付かない欄やメソッドは、名前だけでは呼べません。main の中の p1.setPrice(180) のように、実物を指せば呼べます。

なぜ main に static が付いているのか。Java は Main の実物を作らずに、クラスに対して main を呼ぶからです。main が動き出した時点では、Main の実物は1つもありません。そのため main から名前だけで呼べるのは、static の付いたメソッドだけです。

public class Account {
    // ここに private のフィールド owner（String）と balance（int）を書く
    private String owner;
    private int balance;

    // ここに2つを受け取るコンストラクタを書く
    public Account(String owner, int balance) {
        this.owner = owner;
        this.balance = balance;
    }

    // ここに getOwner() と getBalance() を書く
    public String getOwner() { return owner; }
    public int getBalance() { return balance; }

    public void deposit(int amount) {
        // ここに、0以下なら「入金は1円以上にしてください」と出して終わる処理を書く
        if (amount <= 0) {
            System.out.println("入金は1円以上にしてください");
            return;
        }

        // ここに、残高を増やす処理を書く
        balance += amount;
    }

    public void withdraw(int amount) {
        // ここに、残高より多ければ「残高が足りません」と出して終わる処理を書く
        if (amount > balance) {
            System.out.println("残高が足りません");
            return;
        }

        // ここに、残高を減らす処理を書く
        balance -= amount;
    }
}

Ticket.java

package lesson05;

public class Ticket {
    // ここに、次に渡す番号 nextNo（static、最初は 1）を書く
    private static int nextNo = 1;

    private int no;
    private String name;

    public Ticket(String name) {
        // ここで no に番号を入れ、nextNo を1増やす
        this.no = nextNo;
        nextNo++;
        this.name = name;
    }

    public void show() {
        System.out.println(no + "番 " + name + "さん");
    }

    // ここに、発行した枚数を返す static メソッド getIssued() を書く
    public static int getIssued() { return nextNo - 1; }
}

TicketMain.java

package lesson05;

public class TicketMain {
    public static void main(String[] args) {
        Ticket t1 = new Ticket("高橋");
        Ticket t2 = new Ticket("山田");
        Ticket t3 = new Ticket("佐藤");

        t1.show();
        t2.show();
        t3.show();
        System.out.println("発行した枚数: " + Ticket.getIssued() + "枚");
    }
}

実行結果

1番 高橋さん 2番 山田さん 3番 佐藤さん 発行した枚数: 3枚
nextNo に static が付いているのが要点です。付けないと、整理券1枚1枚が自分の nextNo（最初は1）を持つので、全員が1番になります。番号 no のほうには付けません。番号は1枚ずつ違うからです。

次回は、継承・オーバーライド・super です。普通の会員とゴールド会員は、名前の持ち方・金額の計算・表示が同じで、違うのは割引率だけです。種類ごとにクラスを丸ごと書き写すと、同じ行が何度も並びます。次回は、元のクラスを引き継いで、違う所だけを書く方法を扱います。

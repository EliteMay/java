① 今日の主役

UML での意味

言葉意味
クラス図プログラムを構成するクラスと、その属性（フィールド）・操作（メソッド）、クラスどうしの関係を表す UML の図。いつでも変わらないプログラムの形を表します。
オブジェクト図ある時点で存在するインスタンスと、その値、インスタンスどうしのつながりを表す UML の図。

たとえで言うと

クラス図は「プログラムの間取り図」です

家の中を歩き回らなくても、どこにどんな部屋があり、どうつながっているかが1枚で分かります。

どちらも、中を歩き回らずに全体の形が1枚で分かる

間取り図には、部屋の名前・広さ・設備と、部屋どうしをつなぐドアが描いてあります。住んでいる人や、その日の家具の置き方は描きません。いつ見ても変わらない形だけを描きます。

クラス図も同じです。クラス1つを箱1つで描き、中に「持っている値」と「できること」を書き、クラスどうしのつながりを線で結びます。ファイルを1つずつ開かなくても、プログラム全体の形が1枚で分かります。

人が住んでいる「ある日の写真」に当たるのが、オブジェクト図です。第4回の「たい焼きの型」と「焼いたたい焼き」を、それぞれ図にしたのがクラス図とオブジェクト図です。

たとえJava では
間取り図クラス図
部屋1つクラス1つ。3段の箱で描く
部屋の名前・広さ・設備クラス名・属性（フィールド）・操作（メソッド）
部屋をつなぐドアクラスどうしをつなぐ線
人が住んでいる、ある日の写真オブジェクト図。ある瞬間のインスタンスと値

なぜ必要か

クラス図ファイルを1つずつ開かなくても、どんなクラスがあり、どうつながっているかを1枚で見渡すためです。
オブジェクト図クラス図だけでは見えにくい、実際に作られるインスタンスと値の様子を確かめるためです。
どんな場面で使う？

使う場面

クラス図設計するとき。プログラム全体の形を人に説明するとき。
オブジェクト図クラス図の線や多重度が正しいかを、具体的な例で確かめるとき。

ProductDTO.java

package lesson16;

public class ProductDTO {
    private int id;
    private String name;
    private int price;
    private int stock;

    public ProductDTO(int id, String name, int price, int stock) {
        this.id = id;
        this.name = name;
        this.price = price;
        this.stock = stock;
    }

    public int getId() { return id; }
    public String getName() { return name; }
    public int getPrice() { return price; }
    public int getStock() { return stock; }

    public void setPrice(int price) { this.price = price; }
    public void setStock(int stock) { this.stock = stock; }
}

ProductDAO.java

package lesson16;

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.util.ArrayList;
import java.util.List;

public class ProductDAO {
    private static final String URL = "jdbc:mysql://localhost:3306/stock";
    private static final String USER = "root";
    private static final String PASSWORD = "password";

    // 全部の商品を読む（第11回と同じ）
    public List<ProductDTO> findAll() throws SQLException {
        List<ProductDTO> list = new ArrayList<>();
        String sql = "SELECT id, name, price, stock FROM products ORDER BY id";
        try (Connection con = DriverManager.getConnection(URL, USER, PASSWORD);
             PreparedStatement ps = con.prepareStatement(sql);
             ResultSet rs = ps.executeQuery()) {
            while (rs.next()) {
                list.add(new ProductDTO(rs.getInt("id"), rs.getString("name"),
                                        rs.getInt("price"), rs.getInt("stock")));
            }
        }
        return list;
    }

    // ID で1つ探す。無ければ null を返す
    public ProductDTO findById(int id) throws SQLException {
        String sql = "SELECT id, name, price, stock FROM products WHERE id = ?";
        try (Connection con = DriverManager.getConnection(URL, USER, PASSWORD);
             PreparedStatement ps = con.prepareStatement(sql)) {
            ps.setInt(1, id);
            try (ResultSet rs = ps.executeQuery()) {
                if (rs.next()) {
                    return new ProductDTO(rs.getInt("id"), rs.getString("name"),
                                          rs.getInt("price"), rs.getInt("stock"));
                }
            }
        }
        return null;
    }

    // 追加する。変わった行数を返す
    public int insert(ProductDTO p) throws SQLException {
        String sql = "INSERT INTO products (name, price, stock) VALUES (?, ?, ?)";
        try (Connection con = DriverManager.getConnection(URL, USER, PASSWORD);
             PreparedStatement ps = con.prepareStatement(sql)) {
            ps.setString(1, p.getName());
            ps.setInt(2, p.getPrice());
            ps.setInt(3, p.getStock());
            return ps.executeUpdate();
        }
    }

    // 更新する。変わった行数を返す
    public int update(ProductDTO p) throws SQLException {
        String sql = "UPDATE products SET name = ?, price = ?, stock = ? WHERE id = ?";
        try (Connection con = DriverManager.getConnection(URL, USER, PASSWORD);
             PreparedStatement ps = con.prepareStatement(sql)) {
            ps.setString(1, p.getName());
            ps.setInt(2, p.getPrice());
            ps.setInt(3, p.getStock());
            ps.setInt(4, p.getId());
            return ps.executeUpdate();
        }
    }

    // 削除する。変わった行数を返す
    public int delete(int id) throws SQLException {
        String sql = "DELETE FROM products WHERE id = ?";
        try (Connection con = DriverManager.getConnection(URL, USER, PASSWORD);
             PreparedStatement ps = con.prepareStatement(sql)) {
            ps.setInt(1, id);
            return ps.executeUpdate();
        }
    }
}

ProductService.java

package lesson16;

import java.sql.SQLException;
import java.util.List;

public class ProductService {
    private ProductDAO dao = new ProductDAO();

    public List<ProductDTO> findAll() throws SQLException {
        return dao.findAll();
    }

    public void add(ProductDTO p) throws SQLException {
        check(p);
        dao.insert(p);
    }

    public void update(ProductDTO p) throws SQLException {
        check(p);
        if (dao.update(p) == 0) {
            throw new IllegalArgumentException("ID " + p.getId() + " の商品はありません");
        }
    }

    public void delete(int id) throws SQLException {
        if (dao.delete(id) == 0) {
            throw new IllegalArgumentException("ID " + id + " の商品はありません");
        }
    }

    private void check(ProductDTO p) {
        if (p.getName() == null || p.getName().isBlank()) {
            throw new IllegalArgumentException("商品名を入力してください");
        }
        if (p.getPrice() < 0) {
            throw new IllegalArgumentException("価格に負の値は設定できません");
        }
        if (p.getStock() < 0) {
            throw new IllegalArgumentException("在庫に負の値は設定できません");
        }
    }
}

クラス図で使う記号と書き方

クラスの形は名前・属性・操作の3段。線と矢じりでクラス同士の関係を表す。

- id : int

この部分のコード・詳しい説明を見る

UMLの記法例（Javaコードではありません）

- id : int
+ getId() : int
記号・書き方名前意味と書き方
クラス四角を3段に分けます。1段目にクラス名、2段目に属性（フィールド）、3段目に操作（メソッド）を書きます。
- price : int - name : String = ""属性「可視性 名前 : 型」の順に書きます。初めの値があれば「= 値」を後ろに付けます。Java の private int price; に当たります。
+ getPrice() : int + setPrice(price : int)操作「可視性 名前(引数 : 型) : 戻り値の型」の順に書きます。戻り値が void のときは、省くことが多くあります。
- private + public # protected可視性行の先頭の印です。クラスの外から見えるかどうかを表します。- は private、+ は public、# は protected（子クラスからは見える）です。
下線static のフィールドやメソッドには、下線を引きます。
抽象クラスクラス名を斜体にします。手で書くときは、名前の下に {abstract} と書きます。Java の abstract class です。中身の無いメソッド（抽象操作）も斜体にします。
列挙決まった値だけを持つ型です。Java の enum です。1段目に «enumeration» と名前、2段目に値を並べます。
関連と多重度フィールドに持っている相手へ引く実線です。矢印の先が、持たれる側です。矢印の無い線は、お互いに持つか、まだ決めていないという意味です。相手側の端の数が多重度で、1（ちょうど1つ）、0..1（0か1つ）、0..* または *（いくつでも）、1..*（1つ以上）、2..5（2〜5）と書きます。
ロール名関連の端に書く名前です。持つ側のフィールド名になります。同じクラスの間に関連が2本あるときに書き分けます。
- items : List<Item>型に < >Java のジェネリクスです。「0..* の関連」と「List 型の属性」は、同じことの2通りの書き方です。
依存破線の矢印です。フィールドには持たず、引数・戻り値・メソッドの中の変数として一時的に使うだけの相手へ引きます。フィールドで持つなら関連です。
汎化継承（extends）です。子から親へ実線を引き、親の側に白抜きの三角を付けます。
実現インタフェースの実装（implements）です。クラスからインタフェースへ破線を引き、白抜きの三角を付けます。インタフェースの名前の上には «interface» と書きます。
集約全体と部分の関係で、全体の側に白抜きのひし形を付けます。全体を消しても、部分は残ります。使い方が現場で分かれるので、読めればよく、描くときは関連かコンポジションにします。
コンポジション全体と部分の関係で、全体の側に黒塗りのひし形を付けます。全体を消すと、部分も一緒に消えます。
パッケージタブの付いたフォルダの形です。クラスをまとめる入れ物で、Java の package です。

オブジェクト図で使う記号と書き方

オブジェクト図は、ある時点のインスタンスと実際の値・つながりを表す。

pen : ProductDTO

この部分のコード・詳しい説明を見る
記号・書き方名前意味と書き方
インスタンス1段目に「名前 : クラス名」を書き、下線を引きます。2段目に「属性 = 値」を書きます。操作の段は書きません。
名前の無いインスタンス名前を付ける意味が無いときは、「: クラス名」とだけ書きます。下線は同じように引きます。
リンクインスタンスどうしのつながりです。実線で描き、多重度は書きません。

1　クラス名と属性（①②）

属性は「可視性 名前 : 型」の順番で書く。クラス名は一番上の段。

- id : int

この部分のコード・詳しい説明を見る

① 1段目の ProductDTO（クラス名）

抜き出した箱は、ProductDTO クラスを表しています。箱1つがクラス1つです。箱は、横線で3段に区切ります。

①の1段目には、クラス名を書きます。1段目は省略できません。2段目と3段目は省略できます。つながりだけを見せたいときは、名前だけの箱にします（今日の主役の図）。

② 2段目（属性）

②の2段目は属性です。属性は、クラスが持つフィールドのことです。1行の書き方は「可視性 名前 : 型」です。名前が先、型が後ろで、間に : を入れます。行の先頭の - は可視性の印で、④で説明します。

- id : int は、商品の番号です。Java の private int id; に当たります。- name : String は商品名で、型は文字列の String です。- price : int は価格、- stock : int は在庫の数です。

なぜ書くのか。インスタンス1つ1つが何を持つかを、コードを開かずに見るためです。

よくある間違い：名前と型を、Java の順で書く。- int id と書くと、UML の決まり（名前が先、型が後ろ）と逆になります。図を読む人が、どちらが名前かで止まってしまいます。Java から写すときは「型を後ろへ回して、: を挟む」と覚えてください。

型を後ろへ回して、間に「 : 」を入れる

上の図は、Java の書き方（左）と UML の書き方（右）を並べたものです。1行目は、フィールドの private int id; です。型の int を後ろへ回して、- id : int にします。2行目は、メソッドの public int getId() です。戻り値の型を最後へ回して、+ getId() : int にします。3行目の public void setPrice(int price) は、引数のあるメソッドです。引数も price : int と、名前を先に書きます。戻り値の無い void も、最後に : void と書きます。

2　操作・可視性・下線（③④⑤）

操作はメソッドを表す。+ はpublic、- はprivate。staticは下線で示す。

+ getId() : int

この部分のコード・詳しい説明を見る

③ 3段目（操作）

③の3段目は操作です。操作は、クラスが持つメソッドのことです。1行の書き方は「可視性 名前(引数) : 戻り値の型」です。引数は、丸括弧の中に 名前 : 型 で書きます。複数あれば , で区切ります。

+ ProductDTO(id : int, name : String, から次の行までは、コンストラクタです。id・name・price・stock の4つを受け取ります。コンストラクタは値を返さないので、戻り値の型を書きません。

getId()・getName()・getPrice()・getStock() は、getter です。getter は、フィールドの値を返すメソッドです。引数が無いので、丸括弧の中は空です。後ろの : int や : String が、返す値の型です。

setPrice(price : int) : void と setStock(stock : int) : void は、setter です。setter は、受け取った値をフィールドに入れるメソッドです。何も返さないので、最後は : void です。戻り値が void のときは、: void を省いても構いません。

何を渡せば何が返るかが分かるので、呼び出し方が図だけで分かります。

④ 行の先頭の - と +（可視性）

④は、行の先頭の - と + です。これを可視性と言います。可視性は、クラスの外から見えるかどうかの印です。- は private、+ は public です。

抜き出した図では、いちばん上の属性 - stock : int が - です。コードの private int stock; に当たります。操作は、すべて + です。+ getStock() : int は、コードの public int getStock() に当たります。

なぜ書くのか。カプセル化できているかが、見た目で分かるからです。カプセル化は、フィールドを private にして、メソッドを通して使わせることです（第5回）。もし price を public にすると、2段目に + price : int が混ざります。コードを読まなくても、カプセル化が崩れていると分かります。

⑤ ProductDAO の2段目の下線

⑤は、ProductDAO の2段目の3行に引いた下線です。下線は、static の印です。static は、インスタンスごとではなく、クラスに1つだけあるものです（第5回）。インスタンスごとに持つものと、クラスに1つだけのものを見分けるために引きます。

3つとも、コードでは private static final String と書いたフィールドです。だから、先頭が - で、型が String です。URL は、つなぐデータベースの場所です。USER と PASSWORD は、MySQL に入るときの名前とパスワードです。

3　関連と多重度（⑥⑦）

関連は実線で結び、1・0..* などの多重度で個数を表す。

1 / 0..*

この部分のコード・詳しい説明を見る

⑥ 上から下へ向かう実線の矢印（関連）

上の箱が ProductService、下の箱が ProductDAO です。上の箱のいちばん下の行 - check(p : ProductDTO) : void は、private のメソッドです。だから、先頭が④の - です。

⑥の、上から下へ向かう実線の矢印が関連です。関連は、相手をフィールドとして持ち続けている、という線です。ProductService は、ProductDAO をフィールド dao として持っています。コードでは、private ProductDAO dao = new ProductDAO(); の行です。

線の端の - dao が、そのフィールドの可視性と名前です。フィールド名は、箱の中ではなく、線の端に書きます。両方に書くと、フィールドが2つあるように読めるためです。だから、ProductService の箱の2段目は、空の段になっています。

矢じりの向きは「知っている向き」です。ProductService は ProductDAO を知っていますが、その逆は知りません。だから ProductDAO は、別の画面からもそのまま使えます。

⑦ 1（多重度）

⑦の 1 は多重度です。多重度は、相手をいくつ持つかを表す数です。相手の側の端に書いた数字を読みます。ProductDAO の側に 1 があります。ProductService 1つは、ProductDAO をちょうど1つ持つ、と読みます。

ProductService の側の端には、数字がありません。数字が無い端は、数を決めていない（この図では問わない）という意味です。

なぜ書くのか。何個持つかで、フィールドの書き方が決まるからです。

よく使う書き方を、下の表にまとめます。

4　依存と、ほかの線（⑧）

依存は破線の矢印。継承は白い三角の矢じり。線の種類に意味がある。

implements / extends

この部分のコード・詳しい説明を見る

⑧ 破線の矢印（依存）

左が ProductService、右が ProductDTO の箱です。⑧の破線の矢印が依存です。依存は、引数や戻り値で使うだけで、フィールドには持っていない、という線です。ProductService は、add(p : ProductDTO) の引数や、findAll() の戻り値で ProductDTO を使います。でも、ProductDTO のフィールドは持っていません。だから破線です。関連と同じく、使う側から使われる側へ矢印を引きます。

全体の図では、ProductDAO から ProductDTO へも、同じ破線（⑧）を引いています。ProductDAO も、insert の引数や findById の戻り値で使うだけだからです。

なぜ関連と分けるのか。持ち続けるのか、その場で使うだけなのかで、つながりの強さが違うからです。ProductDTO を直すと、破線でつながったクラスにも直しが及びます。

左の箱 ProductService の中身

右の箱の ①②④ は、前の節で説明した所です。ProductService の2段目は空です。フィールドの dao は、⑥の線の端に書いたからです。左の箱の下の端から出ている線が、その⑥の関連の線です。

ProductService の3段目には、5つのメソッドが並んでいます。findAll() は、全部の商品を List<ProductDTO> で返します。add と update は、ProductDTO を受け取り、追加・更新します。delete は、int の ID を受け取り、削除します。この3つは何も返さないので、: void です。check は、入力の検査をする private のメソッドです。

よくある間違い：フィールドで持っているのに、破線で描く。ProductService は、private ProductDAO dao = new ProductDAO(); と持ち続けています。だから、ProductDAO への線は実線の関連です。見分け方は「フィールドに書いてあるか」だけです。

クラス図の線には、ほかに汎化・実現・集約・コンポジションがあります。今日の2本と合わせて、1枚にまとめます。

矢じり・三角・ひし形の形と、実線か破線かで描き分ける

1行目・2行目　関連と依存

1行目と2行目は、今日写した関連と依存です。関連は実線と開いた矢じりで、フィールドとして持つときに使います。依存は破線と開いた矢じりで、引数・戻り値で使うだけのときに使います。

3行目・4行目　汎化と実現

3行目から下の4本は、今日の図には出てきません。

3行目の汎化は、継承（extends）です。実線の先に、白抜きの三角を付けます。4行目の実現は、インタフェースの実装（implements）です。破線の先に、白抜きの三角を付けます。どちらも、三角は親（インタフェース）の側に付けます。違いは、実線か破線かです。

三角はどちらも白抜きで、親（インタフェース）の側。違いは実線か破線か

左　Member と GoldMember（汎化）

左は汎化の例です。GoldMember が Member を継承しています。子の GoldMember から親の Member へ実線を引き、親の側に三角を付けています。2つの箱は、名前だけを書いて、2段目と3段目を省いています。

右　Coupon と PercentCoupon（実現）

右は実現の例です。Coupon の名前の上の «interface» は、インタフェースであることを示す印です。第15回の «include» と同じ、ステレオタイプの書き方です。Coupon は、2段目を省き、3段目に2つのメソッドを書いています。getName() はクーポンの名前を、apply(price : int) : int は割り引いたあとの価格を返します。

PercentCoupon は、Coupon を実装したクラスです。2段目の - rate : int は、割り引く割合です。3段目は、rate を受け取るコンストラクタと、Coupon のメソッドを書き直した2つです。PercentCoupon から Coupon へ破線を引き、Coupon の側に三角を付けています。子の箱には、コードで子に書いたもの（書き直したメソッドなど）だけを書きます。

よくある間違い：汎化の三角を、子の側に付ける。三角は「こちらが親」という印です。線は子から親へ引きます。三角は、extends の右に書いたクラスの側に付けます。

5行目・6行目　集約とコンポジション

表の5行目の集約と、6行目のコンポジションは、どちらも「全体と部分」の関係です。どちらも、全体の側の端にひし形を付けます。決め手は「全体を消したとき、部分も一緒に消えるか」です。消えるなら黒塗りのひし形（コンポジション）、残るなら白抜きのひし形（集約）です。Java のコードでは、部分を全体の中だけで new しているなら、コンポジションです。外で作ったものを受け取って持つなら、集約です。

⑨ インスタンスの箱 pen : ProductDTO

1段目の pen : ProductDTO は、「インスタンス名 : クラス名」の形です。下線を引きます。pen は、見分けるために付けた名前です。コードの変数名ではありません。名前が要らなければ、: ProductDTO と書きます。

2段目には、そのときの値を「属性名 = 値」で書きます。id = 1 は、表の1件目の ID です。name = "ボールペン" は商品名です。文字列なので " で囲みます。price = 150 は価格150円、stock = 30 は在庫30個です。どれも、表を3件に戻す SQL で入れた1件目の値です。

SQL・JDBC・PreparedStatement

データベースへの命令とJavaの処理をつなげて考える。

まず結論

SQLはデータベースへの命令。JDBCはJavaからSQLを実行する仕組み。PreparedStatementに?を使うと、入力値をSQL文字列へ直接連結せず安全に渡せる。

コードと結果で確認

まず実際にどう動くかを見て、その理由を下で整理する。

JDBCの抜粋（接続済みのconnが必要）
String sql = "SELECT name FROM products WHERE id = ?";

try (PreparedStatement ps = conn.prepareStatement(sql)) {
    ps.setInt(1, 5);
    try (ResultSet rs = ps.executeQuery()) {
        while (rs.next()) {
            System.out.println(rs.getString("name"));
        }
    }
}
実行結果
id=5の商品名があれば表示（DBのデータ次第）

1行ずつ考えると

  1. SELECT name FROM products WHERE id = ? は、idに応じた商品名を取得するSQL。
  2. ps.setInt(1,5) は最初の ? に整数5を設定する。
  3. executeQuery()で取得し、rs.next()で行を順に進める。

ここで間違えやすい

よくある勘違いこのコードだけでは動かない。接続を表すconn、DBサーバー、テーブル、JDBCドライバなどが必要。?にテーブル名や列名そのものは指定できない。またユーザー入力を直接SQLへ連結するとSQLインジェクションの危険がある。

SQLだけを先に読めるようにする

比較用のコード（必要部分を抜粋）
SELECT name FROM products WHERE id = 5;
INSERT INTO products (id, name)
VALUES (6, 'ノート');
UPDATE products SET name = 'メモ' WHERE id = 6;

SELECTは検索、INSERTは追加、UPDATEは更新。特にUPDATEとDELETEはWHEREを忘れると意図せず多くの行が対象になる。SQLはDB上で実行するため、Javaコードとは分けて読む。

30秒で理解チェック

Javaの入力値をSQLに渡すとき、"... WHERE name = '" + input + "'" と連結するのがよい？

答えと理由を開く

避ける。 SQLに?を入れてPreparedStatementのsetStringなどで渡す。

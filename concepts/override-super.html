継承・オーバーライド・super

親の機能を受け継ぎながら、子の動作だけ変える。

まず結論

extends は親の機能を受け継ぐ。@Override を付けた同じメソッド名・引数なら子の実装が使われる。super は親の実装を呼ぶ手段。

コードと結果で確認

まず実際にどう動くかを見て、その理由を下で整理する。

Main.java（親の処理も呼び、子で追加する）
public class Main {
    static class Animal {
        void speak() {
            System.out.println("動物");
        }
    }

    static class Dog extends Animal {
        @Override
        void speak() {
            super.speak();
            System.out.println("ワン");
        }
    }

    public static void main(String[] args) {
        Animal pet = new Dog();
        pet.speak();
    }
}
実行結果
動物
ワン

1行ずつ考えると

  1. Dog extends Animal で親の機能を受け継ぐ。
  2. Animal pet = new Dog(); は変数の型は親、実体は子。
  3. pet.speak() は実体Dogの処理を呼ぶ。その中の super.speak() は親の処理。

ここで間違えやすい

よくある勘違い引数の数や型が違うと、オーバーライドではなく別のメソッド（オーバーロード）になる場合がある。@Override を付けてコンパイル時に間違いを見つける。

親のコンストラクタを呼ぶsuper(...)とは区別

比較用のコード（必要部分を抜粋）
class Person {
    Person(String name) { System.out.println(name); }
}
class Student extends Person {
    Student(String name) {
        super(name); // 親のコンストラクタ
    }
}

super.speak() は親のメソッド、super(name) は親のコンストラクタを呼ぶ。後者はコンストラクタの最初の文として書く（従来のJavaの授業環境の場合）。

30秒で理解チェック

Animal a = new Dog(); a.speak(); でDog側が親のspeakをオーバーライドしているとき、どちらが動く？

答えと理由を開く

Dog側。 呼び出せるメソッドは変数の型で決まり、どの実装が動くかは実体の型に従う。

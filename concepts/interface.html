インタフェースと多態性

違うクラスなのに、なぜ同じメソッドで呼べるのか。

まず結論

インタフェースは「このメソッドを使える」という約束。implements したクラスはその約束を実装する。変数の型をインタフェースにすれば、種類が違っても同じ処理で扱える。

コードと結果で確認

まず実際にどう動くかを見て、その理由を下で整理する。

Main.java（インタフェース型で2種類を扱う）
public class Main {
    interface Speaker {
        void speak();
    }

    static class Dog implements Speaker {
        public void speak() { System.out.println("ワン"); }
    }
    static class Cat implements Speaker {
        public void speak() { System.out.println("ニャー"); }
    }

    public static void main(String[] args) {
        Speaker[] animals = {new Dog(), new Cat()};
        for (Speaker a : animals) {
            a.speak();
        }
    }
}
実行結果
ワン
ニャー

1行ずつ考えると

  1. Speaker は speak() を使えるという約束だけ定める。
  2. DogとCatはそれぞれimplements Speakerで実装する。
  3. Speaker[]に両方を入れ、同じa.speak()で実物に応じた処理が動く。

ここで間違えやすい

よくある勘違いinterfaceで宣言した通常の抽象メソッドはpublic。実装するときにpublicを省くと、アクセス範囲が狭くなりコンパイルエラーになる。extendsによるクラス継承とimplementsは別。

抽象クラスとの違い

比較用のコード（必要部分を抜粋）
interface Speaker {
    void speak(); // 操作の約束
}

abstract class Animal {
    String name;  // 共通の状態
    abstract void speak();
    void rest() { System.out.println("休む"); }
}

抽象クラスは共通フィールドや実装も持てる。クラスの継承は基本1つ、インタフェースは複数実装できる。最初は「役割の約束」と「共通の土台」で使い分ける。

30秒で理解チェック

Speaker s = new Dog(); s.speak(); でDogの処理が動くのはなぜ？

答えと理由を開く

変数の型はSpeakerでも、実体はDogだから。 これが多態性（ポリモーフィズム）の基本。

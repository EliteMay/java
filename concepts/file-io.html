ファイル入出力とthrows

ファイルがないとき、どこに保存されるか、どう閉じるか。

まず結論

ファイル操作は失敗し得るのでIOExceptionを考える。Path.of("memo.txt")は実行時の作業フォルダを基準にする。読んだ内容を使う操作とファイルの場所を分けて考える。

コードと結果で確認

まず実際にどう動くかを見て、その理由を下で整理する。

Main.java（テキストを書いて読み戻す）
import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;

public class Main {
    public static void main(String[] args) {
        Path file = Path.of("memo.txt");
        try {
            Files.writeString(file, "こんにちは");
            String text = Files.readString(file);
            System.out.println(text);
        } catch (IOException e) {
            System.out.println("ファイル操作に失敗");
        }
    }
}
実行結果
こんにちは（正常に書き込み・読み込みできた場合）

1行ずつ考えると

  1. Path.of("memo.txt")で、ファイル名から場所を指定する。相対パスは作業フォルダ基準。
  2. Files.writeStringで内容を保存し、Files.readStringで全部読む。
  3. 失敗したらIOExceptionをcatchして処理を分ける。

ここで間違えやすい

よくある勘違いFiles.writeStringの標準設定は、すでにファイルがある場合に上書きする。大切なデータの保存では追記・バックアップを検討。Eclipseのプロジェクト名やsrcフォルダと、実行時の作業フォルダは同じとは限らない。

BufferedReaderなどは自動で閉じる

比較用のコード（必要部分を抜粋）
try (var reader = Files.newBufferedReader(
        Path.of("memo.txt"))) {
    System.out.println(reader.readLine());
} catch (IOException e) {
    System.out.println("読めませんでした");
}

try ( ... ) を使うと、自動でcloseされる。上の比較はFiles・Path・IOExceptionをimportした状態の抜粋。

30秒で理解チェック

void load() throws IOException と書けば、ファイル読み込みは必ず成功する？

答えと理由を開く

いいえ。 throwsは例外が起き得ることを宣言するだけ。失敗をなくすのではなく呼び出し元で扱えるようにする。

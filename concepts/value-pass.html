引数・戻り値と値渡し

なぜintの変更は元に戻らず、配列の変更は見えるのか。

まず結論

Javaではメソッドに値のコピーを渡す。int は数字がコピーされ、配列は「配列を指す参照の値」がコピーされる。どちらも値渡し。

コードと結果で確認

まず実際にどう動くかを見て、その理由を下で整理する。

Main.java（値を渡す場合と配列を渡す場合）
public class Main {
    static void changeNumber(int n) {
        n = 99;
    }

    static void changeArray(int[] values) {
        values[0] = 99;
    }

    public static void main(String[] args) {
        int number = 10;
        int[] list = {10, 20};
        changeNumber(number);
        changeArray(list);
        System.out.println(number);
        System.out.println(list[0]);
    }
}
実行結果
10
99

1行ずつ考えると

  1. changeNumber(number) は数字10をコピーして渡す。n=99 でも外の number は10。
  2. changeArray(list) は配列を指す値をコピーする。呼び出し側とメソッド側は同じ配列を指す。
  3. values[0]=99 はその配列の0番を書き換えるため、外側から見ても99になる。

ここで間違えやすい

よくある勘違いvalues = new int[]{1, 2}; とメソッドの中で代入しても、呼び出し元の list が新しい配列に切り替わるわけではない。「配列の中身を変更」と「変数の参照先を変更」は別。

元のintを更新したいなら戻り値を使う

比較用のコード（必要部分を抜粋）
static int doubleIt(int n) {
    return n * 2;
}
// main内
int number = 10;
number = doubleIt(number);
System.out.println(number); // 20

return が結果を返し、呼び出し元で代入し直す。returnした時点でそのメソッドの処理は終わる。

30秒で理解チェック

int a=5; をメソッドへ渡し、メソッド内で引数に10を代入。呼び出し元の a は？

答えと理由を開く

5。 引数はコピー。更新した結果がほしいならreturnで受け取り直す。

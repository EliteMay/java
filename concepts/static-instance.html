static・private・インスタンス

みんなで共有する値と、1個ずつ持つ値を見分ける。

まず結論

static はクラス側の共有メンバー。普通のフィールドは new したインスタンスごと。private は外部から直接変更させないための制限。

コードと結果で確認

まず実際にどう動くかを見て、その理由を下で整理する。

Main.java（共有の数と個別の名前）
public class Main {
    static class Product {
        static int total = 0;
        private String name;

        Product(String name) {
            this.name = name;
            total++;
        }

        String getName() { return name; }
    }

    public static void main(String[] args) {
        Product a = new Product("A");
        Product b = new Product("B");
        System.out.println(Product.total);
        System.out.println(a.getName());
        System.out.println(b.getName());
    }
}
実行結果
2
A
B

1行ずつ考えると

  1. Product.total はクラス全体で1つ。new を2回するとコンストラクタが2回増やす。
  2. name はそれぞれの実物が持つので、aはA、bはB。
  3. private name は外から直接書き換えられない。ここでは getName() で読むことだけ許可している。

ここで間違えやすい

よくある勘違いstatic は「どこからでも自由に触れる」という意味ではない。static private も可能。またstaticメソッドでは、インスタンスを指定せずに this.name に直接アクセスできない。

「共有」だけしたいのか「守りたい」のかを分ける

比較用のコード（必要部分を抜粋）
// クラスに1個だけある値
static int count;

// インスタンスごとに違う値
private int stock;

// 中身を守りつつ読み取りだけ許可
int getStock() { return stock; }

static は所属を決め、private はアクセスを制限する。別の役割のキーワードなので同時にも使える。

30秒で理解チェック

Product p1 = new Product("A"); と p2 の2つを作った。static int total の保存先は何個？

答えと理由を開く

1個。 staticはクラスに属し、インスタンスの数だけ増えるわけではない。値はコンストラクタの処理で増やしている。

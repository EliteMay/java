nullと例外処理

null、try、catch、throwsの役割を混ぜない。

まず結論

null は参照先がないこと。例外は実行中の失敗を表す仕組み。try-catch は失敗時の処理を決めるものだが、元の問題が自動で直るわけではない。

コードと結果で確認

まず実際にどう動くかを見て、その理由を下で整理する。

Main.java（nullが原因の例外を捕まえる）
public class Main {
    public static void main(String[] args) {
        String name = null;

        try {
            System.out.println(name.length());
        } catch (NullPointerException e) {
            System.out.println("名前がありません");
        }
        System.out.println("次の処理");
    }
}
実行結果
名前がありません
次の処理

1行ずつ考えると

  1. name には文字列の参照先がない。
  2. name.length() を呼ぶと NullPointerException が起きる。
  3. 対応するcatchへ移動し、メッセージを表示したあと、後続の処理へ進む。

ここで間違えやすい

よくある勘違いString name=""; は空文字で、nullとは違う。空文字ならname.length()は0。catch (Exception e)で何でも捕まえると原因に気付きにくいことがある。

そもそも例外を起こさない書き方

比較用のコード（必要部分を抜粋）
String name = null;
if (name != null) {
    System.out.println(name.length());
} else {
    System.out.println("名前を入力してください");
}

値がないことが普通に起こる場合は、例外を待つより先に条件で分ける。throw は例外を投げる命令、throws は呼び出し元に扱いを任せる宣言。

30秒で理解チェック

String text = ""; の text.length() は例外になる？

答えと理由を開く

ならない。結果は0。 空文字は長さ0の文字列オブジェクト。nullはオブジェクトを指していない。

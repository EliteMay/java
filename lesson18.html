ステートマシン図

第22章 22-2　ステートマシン図 ／ 状態と遷移 ／ ガード条件 ／ 図をコードにする

今日の主役

ステートマシン図　ガード条件

今日できるようになること
  • 商品1件の状態の移り変わりを、ステートマシン図で描ける
  • ガード条件を、どの値でも1つだけに当てはまるように書ける
  • 図の矢印を if にして、図に無い移り方を断れる
① 今日の主役

UML での意味

言葉意味
ステートマシン図1つのオブジェクトが取りうる状態と、どのイベントでどの状態へ移るか（遷移）を表す UML の図。
ガード条件ステートマシン図の矢印に［ ］で書く条件。条件を満たしたときだけ、その矢印へ進みます。

たとえで言うと

ステートマシン図は「荷物の追跡画面」

宅配の追跡画面は、荷物1個がいまどうなっているかを表しています。

ステートマシン図の見え方。主役は「荷物1個」

追跡画面に出るのは「受付済み」「配送中」「配達済み」です。荷物1個が、いまどうなっているかを表しています。これを描くのがステートマシン図です。

配送中から配達済みへ移るのは、届けに行って、相手が在宅だったときだけです。留守なら配送中のままです。このように、矢印へ進む条件を［ ］で書いたものがガード条件です。

たとえJava では
追跡画面の「配送中」状態。商品なら「在庫あり」「売り切れ」
「発送する」で表示が変わる遷移。商品なら「売る」で在庫ありから売り切れへ移る
在宅のときだけ配達済みになるガード条件。商品なら［在庫と売る数が同じ］のときだけ売り切れへ移る

なぜ必要か

ステートマシン図1つの物が、どの状態からどの状態へ移ってよいか（移ってはいけないか）をはっきりさせるためです。
ガード条件同じきっかけでも、条件によって行き先が変わるからです。

今日は、第10〜14回で作った商品在庫管理アプリの「商品1件」を、ステートマシン図で描きます。まず写します。

Product.java　第5回からの正本（このまま写す）

package lesson18;

public class Product {
    private static int count = 0;

    private int id;
    private String name;
    private int price;
    private int stock;

    public Product(int id, String name, int price, int stock) {
        this.id = id;
        this.name = name;
        this.price = price;
        this.stock = stock;
        count++;
    }

    public int getId() { return id; }
    public String getName() { return name; }
    public int getPrice() { return price; }
    public int getStock() { return stock; }

    public void setPrice(int price) {
        if (price < 0) {
            System.out.println("価格に負の値は設定できません");
            return;
        }
        this.price = price;
    }

    public void setStock(int stock) {
        if (stock < 0) {
            System.out.println("在庫に負の値は設定できません");
            return;
        }
        this.stock = stock;
    }

    public void show() {
        System.out.println(id + " / " + name + " / " + price + "円 / 残り" + stock + "個");
    }

    public static int getCount() { return count; }
}

SellMain.java

package lesson18;

public class SellMain {
    public static void main(String[] args) {
        Product p = new Product(2, "ノート", 220, 3);

        sell(p, 2);
        sell(p, 1);
        sell(p, 1);
    }

    static void sell(Product p, int count) {
        if (p.getStock() == 0) {                  // 売り切れから出る「売る」の矢印は無い
            System.out.println(p.getName() + " : 売り切れなので売れません");
            return;
        }
        if (p.getStock() > count) {               // ［在庫が売る数より多い］
            p.setStock(p.getStock() - count);     // ／在庫を減らす
            System.out.println(p.getName() + " : 在庫あり（残り" + p.getStock() + "個）");
        } else if (p.getStock() == count) {       // ［在庫と売る数が同じ］
            p.setStock(p.getStock() - count);     // ／在庫を減らす
            System.out.println(p.getName() + " : 売り切れ");
        } else {                                  // どの［ ］にも当てはまらない。図に矢印が無い
            System.out.println(p.getName() + " : 在庫が足りないので売れません");
        }
    }
}

ステートマシン図で使う記号と書き方

状態は角丸四角、開始は黒丸、終了は二重丸。矢印は状態を変えるイベントを表す。

● → 状態 → ◎

この部分のコード・詳しい説明を見る
記号・書き方名前意味と書き方
開始疑似状態黒丸です。図の始まりを表します。1枚に1つだけ描きます。
状態角丸四角です。「いまは〜です」と言える言葉（〜中・〜済み・在庫あり）を書きます。「〜する」は書きません。
entry・exit・do状態の中に書く動作です。entry はその状態に入ったとき、exit は出るとき、do はその状態にいる間にすることです。どの矢印から入っても同じ動作を、1か所にまとめられます。
遷移状態から状態へ移る矢印です。矢印の上に「イベント［ガード条件］／動作」の順に書きます。
［在庫と売る数が同じ］ガード条件［ ］の中の条件です。満たしたときだけ、その矢印へ進みます。同じイベントの矢印どうしは、どの値でも1つだけに当てはまるように書きます。
after(30分) when(在庫 < 5)時間イベント・変化イベントafter は決めた時間がたったとき、when は条件が成り立ったときに起きるイベントです。タイムアウトや、値の見張りに使います。
完了遷移イベントの書いていない矢印です。その状態での動作（do）が終わると、自動で移ります。
自己遷移同じ状態へ戻る矢印です。状態は変わらず、動作だけが起きます。
選択遷移の途中のひし形です。［ ］の条件で行き先を分けます。ガード条件付きの矢印を2本描くのと同じ意味です。
複合状態状態の中に、小さな状態と遷移を描いたものです。「処理中」の中に「受付」「審査中」がある、のように描きます。
終了状態二重丸です。そこで終わり、もう何も起きません。いくつ描いても構いません。
売る補充
ありあり・切れあり
切れ×あり
状態遷移表図と同じことを表にしたものです。行が今の状態、列がイベント、ます目が移る先です。見本の「あり」は在庫あり、「切れ」は売り切れ、× は移れないことを表します。日本の設計書では、図より表のほうが多く使われます。Java では enum と switch で書くことが多くあります。

1　開始と状態（①②）

開始疑似状態は図の始まり。状態には「在庫あり」など、いまの様子を書く。

状態は動詞ではなく現在の様子

この部分のコード・詳しい説明を見る

① 黒丸（開始疑似状態）

①の黒丸が開始疑似状態です。「ここから始まる」という印です。1枚に1つだけ描きます。黒丸から出る矢印の上の「登録する」は、始まるきっかけです。商品を登録した直後は「在庫あり」から始まる、と読めます。

② 角丸四角の「在庫あり」（状態）

②の角丸四角が状態です。その商品が、いまどうなっているかを表します。中には、「いまは〜です」と言える言葉を書きます。抜き出した所の状態は「在庫あり」です。全体の図では、もう1つの状態「売り切れ」にも②が付いています。

なぜ状態を分けるのか。状態によって、できることが変わるからです。在庫ありなら売れますが、売り切れなら売れません。

よくある間違い：状態の四角に「売る」と書く。ステートマシン図で、とても多い間違いです。

「〜する」は矢印に書く。四角には「いまは〜です」と言える言葉を書く

上の図は、四角の中に「登録する」「売る」「廃番にする」と書いています。これは作業の順番を並べたもので、次回のアクティビティ図の書き方です。これでは「いまこの商品は売れるのか」が読めません。「いまは在庫ありです」とは言えますが、「いまは売るです」とは言えません。言えないものは四角から出して、矢印に書きます。

下の図が、直したものです。四角には「在庫あり」「売り切れ」と、様子を書いています。「登録する」「売る」「廃番にする」は、矢印に書いています。

2　遷移・自己遷移・終了状態（③④⑤）

遷移の [ガード条件] は動ける条件。条件は重ならず、必要な場合を取りこぼさないようにする。

イベント [条件] / 動作

この部分のコード・詳しい説明を見る

③ 「在庫あり」から「売り切れ」への矢印（遷移）

③の、「在庫あり」から「売り切れ」への矢印が遷移です。状態から状態へ移ることです。矢印には「イベント［ガード条件］／動作」の順に書きます。

最初の「売る」がイベントで、移るきっかけです。［在庫と売る数が同じ］がガード条件で、その矢印へ進む条件です。／の後ろの「在庫を減らす」が動作で、移るときにすることです。つまり、在庫と同じ数を売ったら、在庫を減らして売り切れへ移ります。

［ ］は、動作より先に、売る前の在庫と売る数で決まります。なぜ［ ］を書くのか。同じ「売る」でも、在庫と売る数の関係で行き先が変わるからです。

④ 「在庫あり」に戻る矢印（自己遷移）

④の、「在庫あり」から出て「在庫あり」に戻る矢印が自己遷移です。状態は変わらずに、動作だけが起きることです。矢印の言葉は「売る［在庫が売る数より多い］／在庫を減らす」です。在庫が売る数より多ければ、売ったあとも在庫が残ります。だから在庫ありのままです。3個のノートを2個売って1個になっても「在庫あり」のままだ、と示します。

SellMain.java から、sell メソッドを抜き出しています。行の右のコメントが、図の部品です。

sell メソッドの宣言です。p は売る商品、count は売る数です。static なので、main からインスタンスを作らずに呼べます。

if は、在庫が 0、つまり売り切れかを調べます。売り切れから出る「売る」の矢印は、図にありません。だから「売り切れなので売れません」と表示し、return でメソッドを終えます。

if (p.getStock() > count) {               // ［在庫が売る数より多い］
    p.setStock(p.getStock() - count);     // ／在庫を減らす
    System.out.println(p.getName() + " : 在庫あり（残り" + p.getStock() + "個）");

if の条件 p.getStock() > count が、④の［在庫が売る数より多い］です。中の p.setStock(p.getStock() - count); が、「／在庫を減らす」です。今の在庫から売る数を引いた数を、新しい在庫にしています。そのあと、商品名と「在庫あり（残り◯個）」を表示します。◯は、減らしたあとの在庫です。

    System.out.println(p.getName() + " : 売り切れ");

} else {                                  // どの［ ］にも当てはまらない。図に矢印が無い

最後の else は、どの［ ］にも当てはまらないとき、つまり売る数が在庫より多いときです。図に矢印が無いので、「在庫が足りないので売れません」と表示して、何もしません。

図に無い矢印は、「起きてはいけない移り方」です。コードでは、表示して断る形になります。入荷で売り切れから戻す道は、④自力で書くで足します。

よくある間違い：ガード条件を重ねる。［ ］に当たる2つの if を、重なる条件で書いた形です。Product は写したままです。sell の中の、変えた所だけを抜き出しました。

SellMain.java の sell の［ ］の所（間違いあり）

        if (p.getStock() >= count) {              // ［在庫が売る数以上］　ここが問題
            p.setStock(p.getStock() - count);     // ／在庫を減らす
            System.out.println(p.getName() + " : 在庫あり（残り" + p.getStock() + "個）");

            p.setStock(p.getStock() - count);     // ／在庫を減らす
            System.out.println(p.getName() + " : 売り切れ");
        } else {                                  // どの［ ］にも当てはまらない。図に矢印が無い
            System.out.println(p.getName() + " : 在庫が足りないので売れません");

行の右の // ここが問題 が、変えた2行です。if の条件を p.getStock() >= count にしました。写したコードの > を >= に変えています。［在庫が売る数以上］という意味です。else if の条件は p.getStock() <= count です。== を <= に変えています。［在庫が売る数以下］という意味です。

ほかの行は写したままです。どちらの中でも p.setStock(p.getStock() - count); で在庫を減らします。そのあと、1つ目は「在庫あり（残り◯個）」、2つ目は「売り切れ」と表示します。最後の else は、どの［ ］にも当てはまらないとき、「在庫が足りないので売れません」と表示します。これで実行した結果です。

実行結果

ノート : 在庫あり（残り1個） ノート : 在庫あり（残り0個） ノート : 売り切れなので売れません

1行目は、在庫3個のノートを2個売った結果です。残りは1個で、在庫ありのままです。2行目は、在庫1個に1個売った結果です。売り切れになるはずが、「在庫あり（残り0個）」と出ています。3行目は、在庫が0なので、最初の if で断られています。

在庫1個に1個売る場面は、［在庫が売る数以上］にも［在庫が売る数以下］にも当てはまります。図にすると、「在庫あり」から出る2本の矢印の両方に当てはまり、行き先が2つになった形です。コードでは、先に書いた if へ進んだだけです。ガード条件は、移ってよいどの値でも、必ず1つだけに当てはまるように書きます。写したコードのとおり、［在庫が売る数より多い］と［在庫と売る数が同じ］にすれば、重なりは起きません。

重なりの反対の「抜け」も、同じ種類の間違いです。［在庫が売る数より2個以上多い］と［在庫と売る数が同じ］だけだと、在庫が1個だけ多いときに行き先がありません。どの［ ］にも当てはまらない値は、「売れない」と決めたことになります。売る数が在庫より多いときのように、決めて断るならよいのです。決めずに抜けるのが間違いです。図を描いたら、売る数に在庫より1少ない数・同じ数・1多い数を当てはめてください。行き先がちょうど1つか、断るのかを確かめます。

⑤ 二重丸（終了状態）

⑤の二重丸が終了状態です。その商品の話がそこで終わり、もう何も起きないことを表します。

二重丸へ向かう矢印の「廃番にする」が、終わるきっかけです。廃番は、メーカーが作るのをやめて、店でも扱わなくなることです。左の矢印は「在庫あり」から、右の矢印は「売り切れ」から出ています。どちらからでも廃番にできるので、2つ描いています。終了状態は、いくつ描いても構いません。

理解のチェック ／ 30秒

状態を「売る」と書くのは正しい？

答えと理由を見る

正しくありません。「売る」は遷移のイベントで、状態には「在庫あり」「売り切れ」のように今の様子を書きます。

        if (p.getStock() == 0) {                  // 売り切れから出る「売る」の矢印は無い

        // ここに、個数が1より少なければ「商品名 : 補充できません（個数は1以上）」と表示して終わる処理を書く

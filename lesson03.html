① 今日の主役

Java での意味

言葉意味
メソッド名前を付けた処理のまとまり。名前で呼び出すと、中の処理が実行されます。static int calcTax(int price) { ... }
引数メソッドを呼ぶときに渡す値。メソッドの側では、丸括弧の中に書いた変数（型と名前）で受け取ります。calcTax(1000) // 1000 が引数
戻り値メソッドが処理の結果として、呼び出した側へ返す値。return で返し、返す値の型をメソッド名の前に書きます。何も返さないときは void です。int total = calcTax(1000);
値渡しと参照Java は、引数をいつも値のコピーで渡します（値渡し）。int などは値そのものが、配列や String などの参照型は、中身が置いてある場所（参照）がコピーされます。addStock(stock); // int の値 30 のコピーが渡る addStockAll(stocks); // 配列の場所のコピーが渡る

たとえで言うと

メソッドは「自動販売機」。入れるのが引数、出てくるのが戻り値

お金を入れると、飲み物が出てきます。中の仕組みは知らなくても使えます。

メソッドは自動販売機。引数は「入れるもの」、戻り値は「出てくるもの」

自動販売機にお金を入れると、飲み物が出てきます。入れるものが引数、出てくるものが戻り値です。

calcTax(1000) と書けば、1000 が入り、税込みの 1100 が出てきます。使う側は、中でどう計算しているかを知らなくても使えます。処理をメソッドに分ける一番の理由はこれです。

出てきた飲み物は、受け取らなければ取り出し口に残ったままです。戻り値も同じで、int total = calcTax(1000); のように受け取って初めて使えます。

どちらも書き写した紙が渡る（値渡し）。数字なら数字が、配列なら棚の住所（参照）が書き写される

販売機に渡すものは、いつも書き写したものです。これを値渡しと言います。数字を渡すと、その数字を書き写した紙が渡るので、販売機が紙に書き足しても、手元の数字は変わりません。

配列を渡すときも書き写した紙が渡りますが、書いてあるのは棚の置き場所（住所）です。この住所に当たるのが参照です。販売機はその住所の棚を直接さわれるので、棚の中身を変えると、手元から見ても変わっています。

たとえJava では
お金を入れる引数　calcTax(1000) の 1000
飲み物が出てくる戻り値　return で返す 1100
販売機の名前メソッド名　calcTax
販売機の中の仕組みメソッドの { } の中身
数字を書き写した紙を渡す値渡し。int を渡すと、値のコピーが渡る
棚の住所を書き写した紙を渡すこれも値渡し。配列を渡すと、参照（住所）のコピーが渡り、同じ配列を指す

なぜ必要か

メソッド何度も使う処理を1か所にまとめておけば、書くのも直すのも1回で済むからです。
引数同じメソッドを、渡す値だけ変えて使い回すためです。
戻り値メソッドで出した結果を、呼んだ側が表示や次の計算に使えるようにするためです。
値渡しと参照渡した先で書き換えたとき、元が変わるかどうかが、これで決まるからです。

使う場面

メソッド税込み金額の計算、区切り線の表示のように、プログラムのあちこちで使う処理。
引数商品ごとに金額だけを変えて、同じ税込み計算をするとき。
戻り値税込み金額を計算して受け取り、合計に足すとき。
値渡しと参照メソッドに渡した値や配列を、メソッドの中で書き換えるとき。

全体像

プロジェクトの中身。最初はこの1つのファイルだけです

Main.java

package lesson03;

public class Main {
    public static void main(String[] args) {
        printLine();                                  // ① 呼び出し
        int total = calcTax(1000);                    // ④ 受け取る
        System.out.println("税込み : " + total + "円");

        int stock = 30;
        addStock(stock);                              // ⑤ int を渡す
        System.out.println("stock : " + stock + "個");

        int[] stocks = {30, 12, 5};
        addStockAll(stocks);                          // ⑥ 配列を渡す
        System.out.println("stocks[0] : " + stocks[0] + "個");
        printLine();                                  // ① 呼び出し
    }

    static void printLine() {                         // ① メソッド
        System.out.println("--------------------");
    }

    static int calcTax(int price) {                   // ② 引数と戻り値の型
        return price * 110 / 100;                     // ③ return
    }

    static void addStock(int s) {                     // ⑤ int を受け取る
        s += 10;
    }

    static void addStockAll(int[] s) {                // ⑥ 配列を受け取る
        for (int i = 0; i < s.length; i++) {
            s[i] += 10;
        }
    }
}

stock は 30 のまま、stocks[0] は 40 に変わりました。どちらも「10 足す」メソッドに渡したのに、結果が分かれています。これが今日の山場です。理由は③解説の3と4で説明します。

③ 解説

写したコードを、行の右の番号の順に説明します。説明する所のコードを、それぞれの頭に抜き出しています。よくある間違いも一緒に見ます。

1　メソッドを作って呼ぶ（①）

public static void main(String[] args) {
    printLine();                                  // ① 呼び出し
    // （中略）
    printLine();                                  // ① 呼び出し
}

static void printLine() {                         // ① メソッド
    System.out.println("--------------------");
}

static void printLine() { ... } がメソッドを作る所、printLine(); が呼び出す所です。printLine(); の行に来ると下の { } の中へ飛び、終わると元の行の次へ戻ります。void は「何も返さない」という意味です。

このコードでは、同じ区切り線を main の最初と最後の2か所で出しています。printLine にまとめてあるので、線の形を変えたいときは printLine の中の1行を直せば、2か所とも変わります。

よくある間違い：static を付け忘れる。printLine から static を消すと、呼び出す行がエラーになります。

Main.java（間違いあり）

package lesson03;

public class Main {
    public static void main(String[] args) {
        printLine();                                  // エラー
        System.out.println("商品在庫管理");
        printLine();                                  // エラー
    }

    void printLine() {                                // static が無い
        System.out.println("--------------------");
    }
}

エラーメッセージ（Eclipse）

型 Main の非 static メソッド printLine() を static 参照することはできません （Cannot make a static reference to the non-static method printLine() from the type Main）

main は、プログラムを始めるときに JVM がインスタンスを作らずに呼ぶので、必ず static を付けます。static の付いたメソッドから名前だけで呼べるのは、static の付いたメソッドだけです。そのため printLine にも static を付けます。今日は「main から呼ぶメソッドには static を付ける」と覚えてください。意味は第5回で扱います。

2　引数を渡し、戻り値を受け取る（②③④）

static int calcTax(int price) {                   // ② 引数と戻り値の型
    return price * 110 / 100;                     // ③ return
}

static int calcTax(int price) の、丸括弧の中の int price が引数（受け取る値）、名前の前の int が戻り値の型（返す値の型）です。呼ぶ側に書く calcTax(1000) の 1000 も、引数と呼びます。price は呼ぶたびに渡された値になるので、計算の式は1つのままで、どの金額にも使えます。

return は、値を返してメソッドを終える命令です。1.1 を掛けると小数（double）になり int に入らないので、110 / 100 で 1.1 倍しています。

int total = calcTax(1000);                    // ④ 受け取る
System.out.println("税込み : " + total + "円");

int total = calcTax(1000); は、返ってきた 1100 を total に入れます。戻り値は受け取らないと、その場で捨てられます。受け取らずに式の中でそのまま使うこともできます。calcTax(150) + calcTax(220) は 165 + 242 で 407 です。

よくある間違い：表示するだけのメソッドから、値を受け取ろうとする。

Main.java（間違いあり）

package lesson03;

public class Main {
    public static void main(String[] args) {
        int total = calcTax(1000);                    // エラー
        System.out.println("税込み : " + total + "円");
    }

    static void calcTax(int price) {                  // 表示して終わり
        System.out.println(price * 110 / 100);
    }
}

エラーメッセージ（Eclipse）

型の不一致: void から int には変換できません （Type mismatch: cannot convert from void to int）

void は「画面に出して終わり」、戻り値は「手渡し」

void のメソッドは何も返さないので、total に入れるものがありません。計算するメソッドは、calcTax のように int と return で値を返し、表示は呼んだ側でします。

戻り値の型を int にしたのに return を書き忘れると、「このメソッドは型 int の結果を戻す必要があります」（This method must return a result of type int）というエラーになります。

3　int を渡す（⑤）

public static void main(String[] args) {
    // （中略）
    int stock = 30;
    addStock(stock);                              // ⑤ int を渡す
    System.out.println("stock : " + stock + "個");
    // （中略）
}

static void addStock(int s) {                     // ⑤ int を受け取る
    s += 10;
}

addStock は在庫を 10 個増やすつもりのメソッドですが、stock は 30 のままでした。エラーは出ません。

int を渡すと、値のコピーが渡る（値渡し）

メソッドに int を渡すと、値のコピーが渡ります。s は stock の値 30 をコピーした別の変数で、s += 10 で変わるのは s だけです。s はメソッドが終わると消えます。変数が使えるこの範囲をスコープと言います。引数の名前を s から stock に変えても同じです。名前が同じでも、メソッドが違えば別の変数です。

ここで出た言葉値渡し　変数の中身をコピーして渡すこと。Java は、引数をいつもこの形で渡しますスコープ　変数が使える範囲。宣言した { } の中だけです。引数はそのメソッドの中だけで使えます

増やしたいときは、変えた結果を戻り値で返し、呼んだ側で受け取り直します。

Main.java（戻り値で受け取り直す形）

package lesson03;

public class Main {
    public static void main(String[] args) {
        int stock = 30;
        stock = addStock(stock);                      // 返ってきた値で入れ直す
        System.out.println("stock : " + stock + "個");
    }

    static int addStock(int s) {                      // int を返す
        return s + 10;
    }
}

実行結果

stock : 40個

4　配列を渡す（⑥）

public static void main(String[] args) {
    // （中略）
    int[] stocks = {30, 12, 5};
    addStockAll(stocks);                          // ⑥ 配列を渡す
    System.out.println("stocks[0] : " + stocks[0] + "個");
    // （中略）
}

static void addStockAll(int[] s) {                // ⑥ 配列を受け取る
    for (int i = 0; i < s.length; i++) {
        s[i] += 10;
    }
}

addStockAll も同じ「10 足す」ですが、こちらは stocks[0] が 40 に変わりました。

配列を渡すと、住所のコピーが渡る。行き先は同じ配列

配列の変数が持っているのは、中身ではなく、中身が置いてある場所（住所）です。メソッドに渡るのは住所のコピーなので、s と stocks は同じ1つの配列を指します。そこへ s[i] += 10 と書き込めば、main から見ても変わっています。

渡すものコピーされるものメソッドの中で書き換えると
int などの基本データ型値そのもの元は変わらない（addStock）
配列などの参照型住所中身（s[i]）を書き換えると、元も変わる（addStockAll）
よくある間違い：表示するだけのつもりのメソッドで配列に書き込むと、元の値まで変わってしまいます。addStockAll は在庫を増やしたいので、元が変わってよいのです。変えてよいかを決めてから書きます。

④ 自力で書く　1　Rank

Rank.java

package lesson03;

public class Rank {
    public static void main(String[] args) {
        System.out.println("85点 : " + getRank(85));
        System.out.println("70点 : " + getRank(70));
        System.out.println("40点 : " + getRank(40));
    }

    // ここに getRank を書く（80以上 "A"、60以上 "B"、それ未満 "C" を返す）
    static String getRank(int score) {
        if (score >= 80) {
            return "A";
        } else if (score >= 60) {
            return "B";
        } else {
            return "C";
        }
    }
}

実行結果

85点 : A 70点 : B 40点 : C
return はそこでメソッドを終わらせます。85 のときは return "A"; で終わるので、下の条件は調べられません。60以上を先に書くと、85 も B になります。
④ 自力で書く　2　PriceList

PriceList.java

package lesson03;

public class PriceList {
    public static void main(String[] args) {
        int[] prices = {150, 220, 100};

        System.out.println("合計 : " + sum(prices) + "円");
        discountAll(prices, 20);
        System.out.println("値下げ後の合計 : " + sum(prices) + "円");
        System.out.println("1つ目 : " + prices[0] + "円");
    }

    static int sum(int[] prices) {
        // ここに、全部を足した合計を返す処理を書く
        int total = 0;
        for (int p : prices) {
            total += p;
        }
        return total;
    }

    static void discountAll(int[] prices, int yen) {
        // ここに、全部の価格から yen を引く処理を書く
        for (int i = 0; i < prices.length; i++) {
            prices[i] -= yen;
        }
    }
}

実行結果

合計 : 470円 値下げ後の合計 : 410円 1つ目 : 130円
sum は配列を読むだけなので、元は変わりません。discountAll は中身を書き換えるので、main の prices も変わります。③解説の4の表のとおりです。
⑤ まとめ

確認チェック

  • 引数と戻り値を、自動販売機以外の自分のたとえで説明できる
  • int を渡したときと配列を渡したときで、元が変わるかどうかを、理由と一緒に言える
  • 「渡したのに変わらない」コードを、戻り値で受け取り直す形に直せる

用語の説明

言葉読み方意味
インスタンスいんすたんすクラスから作った実体。第4回で扱います
メソッドめそっどひとまとまりの処理に名前を付けたもの。名前() と書いて呼び出すと、中身が動きます
呼び出すよびだすprintLine(); のように書いて、そのメソッドを動かすこと。終わると呼んだ行の次へ戻ります
引数ひきすうメソッドに渡す値。呼ぶ側に書く値（calcTax(1000) の 1000）と、メソッドの丸括弧で受け取る変数（calcTax(int price) の price）を、どちらも引数と呼びます

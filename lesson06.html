① 今日の主役

Java での意味

言葉意味
継承あるクラス（親クラス）のフィールドとメソッドを引き継いで、新しいクラス（子クラス）を作る仕組み。子クラスには、追加や変更する所だけを書きます。親にできるクラスは1つだけです。public class GoldMember extends Member { ... }
オーバーライド親クラスにあるメソッドを、子クラスで同じ名前・同じ引数のまま書き直すこと。@Override public int getDiscountRate() { return 10; }
super親クラスを指す言葉です。super(...) で親のコンストラクタを、super.メソッド名() で親のメソッドを呼びます。super(name); super.show();

たとえで言うと

継承は「基本の規約をそのまま使い、違う所だけ付則に書く」ことです

会員の種類が増えても、規約を丸ごと書き写したりはしません。

継承は、基本の規約を引き継いで、違う所だけを付則に書くこと

普通の会員もゴールド会員も、名前の持ち方・金額の計算・表示のしかたは同じです。違うのは割引率だけです。基本の規約を1つ作り、ゴールド会員の付則には「割引率は10%」とだけ書きます。

Java も同じです。GoldMember extends Member と書くと、Member に書いたフィールドとメソッドが GoldMember に引き継がれます。これが継承です。子のほうに書くのは、親と違う所だけです。

共通の部分が1か所にまとまるので、計算のしかたを直すときも Member の1か所で済みます。種類ごとに書き写していたら、直し忘れが出ます。

継承を使ってよいのは、「子は親の一種」と言えるときです。「ゴールド会員は会員の一種」は言えますが、「注文は商品の一種」は言えません。注文は商品を継承しません。

オーバーライドは「付則で条文を書き換える」、super は「付則から『基本の規約のとおり』と呼び出す」

付則で、基本の規約の条文を書き換えることをオーバーライドと言います。ゴールド会員の付則は、「割引率」の条文だけを書き換えています。

付則の中で「名前の登録は、基本の規約のとおり」と、基本の規約を呼び出すのが super です。

たとえJava では
基本の会員規約親クラス　Member
ゴールド会員の付則子クラス　public class GoldMember extends Member
付則に書かない条文そのまま引き継がれる　show() calcPrice()
付則で差し替える条文子で書き直すメソッド　getDiscountRate()
条文を付則で書き換えるオーバーライド　@Override
「基本の規約のとおり」と呼び出すsuper　super(name);

なぜ必要か

継承共通の部分を何度も書かず、違う所だけを書くためです。共通の部分を直すときも、親の1か所で済みます。
オーバーライド親と同じ呼び方のまま、子に合った動きに変えるためです。
super子クラスからは、親の private なフィールドに直接値を入れられないので、親に頼んで入れてもらうためです。super.メソッド名() は、親の処理をそのまま使い、そこに付け足すためです。

使う場面

継承普通会員とゴールド会員のように、「〜の一種」と言える関係のクラスを作るとき。
オーバーライド会員の種類ごとに、割引率だけを変えるとき。
super子クラスのコンストラクタで、親の部分に値を入れるとき。親のメソッドの動きに、少し付け足したいとき。

全体像

プロジェクトの中は、次の3つのファイルだけです。どれも1行目は package lesson06; です。

Member のフィールド name は private にして、読み出し用の getName() を付けています。

下の3つが、それぞれのファイルの中身の全部です。行の右にある ①〜⑥ は、③解説の番号です。

プロジェクトの中身。この3つのファイルで全部です

Member.java　親クラス

package lesson06;

public class Member {
    private String name;

    public Member(String name) {
        this.name = name;
    }

    public String getName() { return name; }

    public int getDiscountRate() {                // ① 割引率
        return 0;
    }

    public int calcPrice(int price) {             // ② 共通の計算
        return price * (100 - getDiscountRate()) / 100;
    }

    public void show() {                          // ② 共通の表示
        System.out.println(name + " / 割引 " + getDiscountRate() + "%");
    }
}

GoldMember.java　子クラス

package lesson06;

public class GoldMember extends Member {   // ③ extends

    public GoldMember(String name) {
        super(name);                              // ④ super
    }

    @Override                                     // ⑤ オーバーライド
    public int getDiscountRate() {                // ⑤ オーバーライド
        return 10;
    }
}

Main.java　使うほう

package lesson06;

public class Main {
    public static void main(String[] args) {
        Member m = new Member("高橋");
        GoldMember g = new GoldMember("山田");

        m.show();
        System.out.println("  1000円 → " + m.calcPrice(1000) + "円");
        g.show();                                                        // ⑥ 書いていないのに呼べる
        System.out.println("  1000円 → " + g.calcPrice(1000) + "円");   // ⑥
    }
}

期待される実行結果

高橋 / 割引 0% 1000円 → 1000円 山田 / 割引 10% 1000円 → 900円

実行するのは Main です。GoldMember には show() も calcPrice() も書いていませんが、山田さんは割引 10%・900円で表示されます。

③ 解説

写したコードを、行の右の番号の順に説明します。説明する所のコードを、それぞれの頭に抜き出しています。よくある間違いも一緒に見ます。

1　違う所を1つのメソッドに切り出す（①②）

Member.java から抜き出しています。

public int getDiscountRate() {                // ① 割引率
    return 0;
}

public int calcPrice(int price) {             // ② 共通の計算
    return price * (100 - getDiscountRate()) / 100;
}

public void show() {                          // ② 共通の表示
    System.out.println(name + " / 割引 " + getDiscountRate() + "%");
}

getDiscountRate() は割引率を答えるメソッドです。普通の会員は 0% なので 0 を返します。なぜメソッドに切り出すのか。会員の種類ごとに違うのは割引率だけなので、そこを1つのメソッドにしておけば、子クラスはここだけ書き直せば済むからです。

calcPrice と show は金額の計算と表示で、どちらも中で getDiscountRate() を呼んでいます。計算と表示は全部の会員で同じなので、親に1回だけ書きます。なぜ 0 と直接書かないのか。getDiscountRate() を呼んでおくと、子が割引率を書き直したとき、計算と表示も子の割引率で動くからです。

2　親を引き継ぎ、名前を親に渡す（③④）

GoldMember.java から抜き出しています。

public class GoldMember extends Member {   // ③ extends

    public GoldMember(String name) {
        super(name);                              // ④ super
    }
    // （中略）
}

extends は「〜を引き継ぐ」という意味です。引き継がれる Member を親クラス、引き継ぐ GoldMember を子クラスと呼びます。名前・計算・表示を書き写さずに使えるので、GoldMember の中には親と違う割引率しか書いていません。

super は「親」を指す言葉です。super(name) で親のコンストラクタを呼び、名前を渡します。なぜ親に渡すのか。name は Member の private フィールドなので、子からは直接入れられないからです。入れるのは親のコンストラクタの仕事です。

よくある間違い：super(...) を書かない。子のコンストラクタで、登録のメッセージだけを出すようにした形です。Member と Main は写したままです。

GoldMember.java（間違いあり）

package lesson06;

public class GoldMember extends Member {

    public GoldMember(String name) {              // エラー
        System.out.println(name + " さんを登録します");
    }

    @Override
    public int getDiscountRate() {
        return 10;
    }
}

エラーメッセージ（Eclipse）

暗黙的スーパー・コンストラクター Member() は未定義です。別のコンストラクターを明示的に呼び出す必要があります （Implicit super constructor Member() is undefined. Must explicitly invoke another constructor）

super(...) を書かないと、引数なしの super() が入る

子のインスタンスを作るときは、先に親の部分を作ります。そのため子のコンストラクタは、1行目で必ず親のコンストラクタを呼びます。自分で書かなければ、Java が引数なしの super(); を入れます。ところが Member にあるのは、名前を受け取る Member(String name) だけです。コンストラクタを自分で書いたクラスには、引数なしのコンストラクタは作られません。

写したコードのとおり、1行目に super(name); を書けば動きます。

super(name); は1行目でなければなりません。メッセージの行より下に書くと、「コンストラクター呼び出しは、コンストラクター内の最初のステートメントである必要があります」（Constructor call must be the first statement in a constructor）というエラーになります。

3　親のメソッドを書き直す（⑤）

@Override                                     // ⑤ オーバーライド
public int getDiscountRate() {                // ⑤ オーバーライド
    return 10;
}

親と同じ名前・同じ引数のメソッドを、子で書き直しています。これをオーバーライドと呼びます。ゴールド会員で違うのは割引率だけなので、そこだけ差し替えます。

@Override は「親のメソッドを書き直しています」という印です。なぜ付けるのか。付けずにメソッド名を getDiscountRete と打ち間違えると、エラーは出ず、新しいメソッドが1つ増えただけになるからです。show() の中では親の getDiscountRate()（0%）が使われ、山田さんの割引が 0% になります。

よくある間違い：綴りを間違える。同じ打ち間違いを、@Override を付けたまま書いた形です。Member と Main は写したままです。

GoldMember.java（間違いあり）

package lesson06;

public class GoldMember extends Member {

    public GoldMember(String name) {
        super(name);
    }

    @Override
    public int getDiscountRete() {                // エラー（Rate → Rete）
        return 10;
    }
}

エラーメッセージ（Eclipse）

型 GoldMember のメソッド getDiscountRete() はスーパータイプ・メソッドをオーバーライドまたは実装する必要があります （The method getDiscountRete() of type GoldMember must override or implement a supertype method）

@Override は「親のメソッドを書き直しています」という印

@Override が付いていると、Java は親に同じ名前・同じ引数のメソッドがあるかを確かめます。Member に getDiscountRete() は無いので、その場でエラーになります。オーバーライドするときは、必ず @Override を付けてください。

getDiscountRate(int price) のように引数を付けた場合も、名前が同じでも別のメソッドとして扱われ、割引は 0% のままです。同じ名前で引数の違うメソッドを並べることをオーバーロードと呼び、オーバーライドとは別物です。@Override を付けていれば、同じエラーで気づけます。

show() を子で書き直すときに親の表示も使いたい場合は、中で super.show(); と書きます。super(...) は親のコンストラクタ、super.メソッド名() は親のメソッドを呼びます。

4　子に書いていないメソッドを呼ぶ（⑥）

Main.java から抜き出しています。

public static void main(String[] args) {
    // （中略）
    GoldMember g = new GoldMember("山田");
    // （中略）
    g.show();                                                        // ⑥ 書いていないのに呼べる
    System.out.println("  1000円 → " + g.calcPrice(1000) + "円");   // ⑥
}

GoldMember に書いていない show() と calcPrice() を呼んでいます。親から引き継いでいるので呼べます。中で呼ぶ getDiscountRate() は、子で書き直したほうが使われるので、割引 10%・900円になります。

よくある間違い：親の private のフィールドを、子で使う。show() を子で書き直し、その中で親のフィールド name を直接使った形です。Member と Main は写したままです。

GoldMember.java（間違いあり）

package lesson06;

public class GoldMember extends Member {

    public GoldMember(String name) {
        super(name);
    }

    @Override
    public int getDiscountRate() {
        return 10;
    }

    @Override
    public void show() {
        System.out.println(name + " / ゴールド会員 / 割引 " + getDiscountRate() + "%");   // エラー
    }
}

エラーメッセージ（Eclipse）

フィールド Member.name は不可視です （The field Member.name is not visible）

private は「そのクラスの中だけ」です。子クラスは親を引き継いでいますが、別のクラスなので、private のフィールドは見えません。name を getName() に変えて、getter を通せば動きます。

もう1つの直し方は、Member のフィールドを protected String name; にすることです。protected は、子クラスと同じパッケージのクラスから使えるようにする修飾子で、private と public の中間です。

修飾子そのクラスの中同じパッケージ別のパッケージの子クラスどこからでも
private○×××
何も書かない○○××
protected○○○×
public○○○○
フィールドは private にして getter を通すのが基本です。protected にすると、子クラスから値を自由に書き換えられるようになります。

用語の説明

この回に出た言葉です。覚えるためではなく、分からなくなったときに引くための表です。

言葉読み方意味
継承けいしょうすでにあるクラスの中身を引き継いで、新しいクラスを作ること
extendsえくすてんず「〜を引き継ぐ」。public class GoldMember extends Member のように書きます。親は1つだけ書けます
親クラスおやくらす引き継がれるほう。スーパークラスとも言います。例では Member
子クラスこくらす引き継ぐほう。サブクラスとも言います。例では GoldMember
Objectおぶじぇくとextends を書かないクラスも、Java が自動で Object というクラスを親にします。Object はすべてのクラスの親です
オーバーライドおーばーらいど親のメソッドを、子で同じ名前・同じ引数のまま書き直すこと
@Overrideあっと おーばーらいど「親のメソッドを書き直しています」という印。親に同じメソッドが無いとエラーにしてくれます
アノテーションあのてーしょん@Override のように @ で始まる印。Eclipse の表示では「注釈」
superすーぱー親を指す言葉。super(name) で親のコンストラクタ、super.show() で親のメソッドを呼びます
オーバーロードおーばーろーど同じ名前で、引数の違うメソッドを並べること。オーバーライドとは別物です
privateぷらいべーとそのクラスの中だけで使える、という修飾子。子クラスからも見えません（第5回）
protectedぷろてくてっど子クラスと、同じパッケージのクラスから使える、という修飾子
修飾子しゅうしょくしpublic private protected など、どこから使えるかを決める言葉（第5回）
getterげったーprivate のフィールドの値を読み出すためのメソッド。getName() など（第5回）
コンストラクタこんすとらくたnew したときに1回だけ動くもの（第4回）。子のコンストラクタは、1行目で親のコンストラクタを呼びます

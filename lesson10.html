Java での意味

言葉意味
ストリームデータを先頭から順に読み書きするための、入出力の仕組み。読み込み用と書き込み用は別で、使い終わったら閉じ（close）ます。try (BufferedReader br = new BufferedReader( new FileReader("products.csv", StandardCharsets.UTF_8))) { // 1行ずつ読む }
CSV項目をカンマで区切って並べた、文字だけのファイルです。1行が1件分のデータです。1,ボールペン,150,30 2,ノート,220,10
検査例外と throws検査例外は、備え（catch か throws）を書かないとコンパイルが通らない例外です（IOException など）。throws は、メソッドの中で起きた例外を呼んだ側に任せる、という宣言です。public List<Product> findAll() throws IOException { ... }

たとえで言うと

ストリームは、ファイルとプログラムをつなぐ「水道管」

水は管の中を一方向に流れます。使い終わったら栓を閉めます。

ストリームは一方通行の管。読む管と書く管を別々に開き、使い終わったら閉める

これまで List に入れた商品は、プログラムを閉じると消えていました。第8回・第9回で、毎回 add し直していたのはそのためです。ファイルに書いておけば、閉じても残ります。

プログラムから、ファイルの中身を直接は触れません。ファイルとプログラムを管でつなぎ、中身を先頭から順に流して受け取ります。この管がストリームです。

管は一方通行です。読むときは「ファイルからプログラムへ」、書くときは「プログラムからファイルへ」の管を、別々に開きます。使い終わったら栓を閉めます。閉め忘れると、書いたはずの中身がファイルに届きません（③の4）。

CSV は1行が1件。項目をカンマで区切って並べた、文字だけのファイル

管で運ぶ中身にも、決まった形があります。1行が1件で、項目をカンマで区切って並べた文字のファイルが CSV です。

「ファイルが無い」は、飛んでくると分かっているボール。throws で呼んだ側に任せる

ファイルを開くと、「ファイルが無い」「読めない」というボール（IOException）が飛んでくることが、前もって分かっています。こうした種類の例外が検査例外です。Java は、自分で受け止める（try-catch）か、「後ろの人に任せます」と先に言っておくかの、どちらかを書かないとコンパイルを通しません。先に言っておくのが throws です。後ろの人とは、そのメソッドを呼んだ側（ここでは Main）のことです。

後ろの人に任せると先に言っておくthrows IOException。検査例外に付ける

なぜ必要か

ストリームプログラムを閉じても消えないように、データをファイルへ書いたり、ファイルから読んだりするためです。
CSV表の形のデータを決まった形の文字で保存でき、Excel などほかのソフトとも受け渡しできるからです。
検査例外と throwsファイルや通信のように、失敗するかもしれないと分かっている処理への備えを、書き忘れさせないためです。

Product.java　商品（第5回と同じ）

package lesson10;

public class Product {
    private static int count = 0;   // 作った商品の数（全体で1つ）

    private int id;
    private String name;
    private int price;
    private int stock;

    public Product(int id, String name, int price, int stock) {
        this.id = id;
        this.name = name;
        this.price = price;
        this.stock = stock;
        count++;
    }

    public int getId() { return id; }
    public String getName() { return name; }
    public int getPrice() { return price; }
    public int getStock() { return stock; }

    public void setPrice(int price) {
        if (price < 0) {
            System.out.println("価格に負の値は設定できません");
            return;
        }
        this.price = price;
    }

    public void setStock(int stock) {
        if (stock < 0) {
            System.out.println("在庫に負の値は設定できません");
            return;
        }
        this.stock = stock;
    }

    public void show() {
        System.out.println(id + " / " + name + " / " + price + "円 / 残り" + stock + "個");
    }

    public static int getCount() { return count; }
}

CsvProductDao.java　products.csv を読み書きする係

package lesson10;

import java.io.BufferedReader;
import java.io.BufferedWriter;
import java.io.FileReader;
import java.io.FileWriter;
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.util.ArrayList;
import java.util.List;

public class CsvProductDao {

    public List<Product> findAll() throws IOException {           // ① throws
        List<Product> list = new ArrayList<>();
        try (BufferedReader br = new BufferedReader(              // ② 読むストリーム
                new FileReader("products.csv", StandardCharsets.UTF_8))) {
            String line;
            while ((line = br.readLine()) != null) {              // ③ 1行ずつ読む
                String[] parts = line.split(",");                 // ④ カンマで分ける
                int id = Integer.parseInt(parts[0]);              // ⑤ 数字にする
                String name = parts[1];
                int price = Integer.parseInt(parts[2]);
                int stock = Integer.parseInt(parts[3]);
                list.add(new Product(id, name, price, stock));    // ⑤ 商品にする
            }
        }
        return list;
    }

    public void saveAll(List<Product> list) throws IOException {  // ① throws
        try (BufferedWriter bw = new BufferedWriter(              // ⑥ 書くストリーム
                new FileWriter("products.csv", StandardCharsets.UTF_8))) {
            for (Product p : list) {
                bw.write(p.getId() + "," + p.getName() + ","      // ⑦ 1行書く
                        + p.getPrice() + "," + p.getStock());
                bw.newLine();                                     // ⑦ 改行する
            }
        }
    }
}

Main.java　使うほう

package lesson10;

import java.io.IOException;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        CsvProductDao dao = new CsvProductDao();

        try {
            List<Product> list = dao.findAll();                   // ⑧ 読む
            for (Product p : list) {
                p.show();
            }

            for (Product p : list) {
                if (p.getId() == 2) {                             // ID 2 の「ノート」を
                    p.setStock(p.getStock() - 3);                 // 3個売った
                }
            }
            dao.saveAll(list);                                    // ⑧ 書き戻す
            System.out.println("保存しました");
        } catch (IOException e) {                                 // ⑧ 受け止める
            System.out.println("ファイルを読み書きできません: " + e.getMessage());
        }
    }
}

1　例外を呼んだ側に任せる（①）

CsvProductDao.java（抜き出し）

throws IOException は、このメソッドの中で起きた IOException は呼んだ側に任せる、という宣言です。IOException は、ファイルが無い・読めない・書けないときの例外です。

なぜ呼んだ側に任せるのか。ファイルが無い・書き込めない、は外の事情で起きる検査例外です。そのとき画面に何と出すかは、呼んだ側の Main が決めます。CsvProductDao の中で表示して終わると、Main は失敗に気づけません。

任された例外は、呼んだ側の Main の try-catch（⑧）で受け止めます。

Main.java（抜き出し）

public static void main(String[] args) {
    CsvProductDao dao = new CsvProductDao();

    try {
        List<Product> list = dao.findAll();                   // ⑧ 読む
        // （中略）
        dao.saveAll(list);                                    // ⑧ 書き戻す
        System.out.println("保存しました");
    } catch (IOException e) {                                 // ⑧ 受け止める
        System.out.println("ファイルを読み書きできません: " + e.getMessage());
    }
}

試しに products.csv の名前を変えて（たとえば products_old.csv）、Main を実行します。findAll の中でファイルを開けずに IOException が起き、①の宣言どおり Main へ渡ります。Main の catch が受け止めて、次の1行を出します。e.getMessage() が、開けなかった理由です。

2　読むストリームを開く（②）

CsvProductDao.java（抜き出し）

public List<Product> findAll() throws IOException {           // ① throws
    List<Product> list = new ArrayList<>();
    try (BufferedReader br = new BufferedReader(              // ② 読むストリーム
            new FileReader("products.csv", StandardCharsets.UTF_8))) {
        // （中略）
    }
    return list;
}

products.csv から読むストリームを開きます。FileReader がファイルにつなぐ管、BufferedReader が1行ずつ汲むバケツです。

どこから来るのか。FileReader と BufferedReader は、メソッドではなく、Java に最初から入っているクラスです。java.io というパッケージに入っていて、CsvProductDao.java の上の import java.io.FileReader; と import java.io.BufferedReader; で使えるようにしています。new FileReader(…) で、そのクラスの実物（インスタンス）を作ります（第4回の new と同じです）。

new BufferedReader(new FileReader(…)) は入れ子で、内側で作った FileReader を、外側の BufferedReader のコンストラクタに渡しています。FileReader には1行ずつ読むメソッドが無いので、1行ずつ読める BufferedReader にかぶせて使います。

FileReader の丸括弧の2つ目の StandardCharsets.UTF_8 は、文字コードの指定です。文字コードは、文字をファイルに保存するときの番号の付け方で、UTF-8 はその決まりの1つです。StandardCharsets も Java に最初から入っているクラス（java.nio.charset パッケージ）で、UTF_8 はそこに用意された「UTF-8」を表す値です。

ここで出た言葉FileReader　ファイルを開いて、文字を読むクラス（java.io）BufferedReader　ほかの読む道具にかぶせて、1行ずつ読めるようにするクラス（java.io）。readLine() で1行読みます文字コード　文字をファイルに保存するときの番号の付け方。UTF-8 など。読むときと書くときでそろえます

なぜ文字コードを書くのか。読むときと書くときで、文字コードをそろえるためです。Java 17 以前の環境では、書かないとそのパソコンの標準の文字コードで読むので、日本語が化けることがあります。別の文字コードで保存されたファイルを読むときも化けます。

try の丸括弧の中で開いたものは、{ } を抜けるときに自動で閉じます。途中で例外が起きても必ず閉じます。閉じないと、ファイルをつかんだままになります。

ここで出た言葉try ( ... )　try-with-resources（とらい・うぃず・りそーしず）と呼ぶ書き方。丸括弧の中で開いたストリームを、{ } を抜けるときに自動で閉じます

readLine() は1行読んで、文字列で返します。読む行が無くなると null を返します。while の丸括弧の中は、br.readLine() で1行読む → その行を line に入れる → line を null と比べる、の順に動きます。ファイルが何行あるかは読む前には分からないので、null を「もう行が無い」の合図にしています。

split(",") は、文字列をカンマの所で切り、配列にします。"1,ボールペン,150,30" は、[0] が "1"、[1] が "ボールペン"、[2] が "150"、[3] が "30" になります。

Integer.parseInt で、文字列の "150" を数字の 150 にします（第9回）。なぜ数字にするのか。ファイルから来るものは、数字に見えても全部文字列だからです。Product のコンストラクタは、ID・価格・在庫を int で受け取ります。

4　書くストリームで書き戻す（⑥⑦）

CsvProductDao.java（抜き出し）

public void saveAll(List<Product> list) throws IOException {  // ① throws
    try (BufferedWriter bw = new BufferedWriter(              // ⑥ 書くストリーム

        for (Product p : list) {

products.csv へ書くストリームを開きます。開いた時点でファイルの中身は空になり、先頭から書き直します（上書き）。list の中身を全部書き直すので、ファイルと list がずれません。文字コードは読むときと同じ UTF-8 にします。

write で、商品の4つの値をカンマでつないだ1行を書き、newLine() で改行を書きます。なぜ newLine() が要るのか。write は改行を書かないからです。無いと 1,ボールペン,150,302,ノート,… のように全部が1行につながり、次に読んだときは在庫302個のボールペン1つになります。エラーは出ません。

よくある間違い：閉じ忘れる。saveAll から try ( ) を外し、close() も書かなかった形です。Product と Main は写経のままです。products.csv を②の3行に戻してから試します。

CsvProductDao.java（間違いあり）

package lesson10;

import java.io.BufferedReader;
import java.io.BufferedWriter;
import java.io.FileReader;
import java.io.FileWriter;
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.util.ArrayList;
import java.util.List;

public class CsvProductDao {

    public List<Product> findAll() throws IOException {
        List<Product> list = new ArrayList<>();
        try (BufferedReader br = new BufferedReader(
                new FileReader("products.csv", StandardCharsets.UTF_8))) {
            String line;
            while ((line = br.readLine()) != null) {
                String[] parts = line.split(",");
                int id = Integer.parseInt(parts[0]);
                String name = parts[1];
                int price = Integer.parseInt(parts[2]);
                int stock = Integer.parseInt(parts[3]);
                list.add(new Product(id, name, price, stock));
            }
        }
        return list;
    }

    public void saveAll(List<Product> list) throws IOException {
        BufferedWriter bw = new BufferedWriter(                   // try ( ) を外した
                new FileWriter("products.csv", StandardCharsets.UTF_8));
        for (Product p : list) {
            bw.write(p.getId() + "," + p.getName() + ","
                    + p.getPrice() + "," + p.getStock());
            bw.newLine();
        }
    }                                                             // close() していない
}

「保存しました」と出ています。ところが、リフレッシュして products.csv を開くと、中身が空になっています。

BufferedWriter は溜めておき、いっぱいになったときや閉じるときにファイルへ流す

BufferedWriter は、write のたびにファイルへ書くのではなく、書いた行をいったん溜めておき、いっぱいになったときや閉じるときに流します。閉じないままプログラムが終わると、溜めた分は捨てられます。しかも FileWriter を開いた時点で、元の中身は空にしてあります。写経のコードのとおり try ( ... ) の中で開けば、{ } を抜けるときに自動で閉じます。

Eclipse では、bw の行に黄色い警告「リソース・リーク: 'bw' が閉じられることはありません」（Resource leak: 'bw' is never closed）が出ます。閉じていない、という意味です。赤ではないので実行できてしまいます。

package lesson10;

import java.io.BufferedReader;
import java.io.FileReader;
import java.io.IOException;
import java.nio.charset.StandardCharsets;

public class CsvCheck {
    public static void main(String[] args) {
        int lineNo = 0;                     // 何行目か
        int ok = 0;                         // 読めた行の数

        try (BufferedReader br = new BufferedReader(
                new FileReader("check.csv", StandardCharsets.UTF_8))) {
            String line;
            while ((line = br.readLine()) != null) {
                lineNo++;

                String[] parts = line.split(",");
                if (parts.length != 4) {
                    System.out.println(lineNo + "行目: 項目の数が違います → " + line);
                    continue;
                }

                // ここに try-catch を書き、1つ目・3つ目・4つ目を Integer.parseInt で数字にする
                try {
                    Integer.parseInt(parts[0]);
                    Integer.parseInt(parts[2]);
                    Integer.parseInt(parts[3]);
                    ok++;
                } catch (NumberFormatException e) {
                    System.out.println(lineNo + "行目: 数字にできません → " + line);
                }
            }
        } catch (IOException e) {
            System.out.println("check.csv を読めません: " + e.getMessage());
        }
        System.out.println("読めた行: " + ok + " / 全部で" + lineNo + "行");

}

確認チェック

  • ストリームは一方通行で、読む管と書く管を別々に開くことを説明できる
  • try ( ... ) で開くと、何が自動で行われるかを説明できる
  • FileWriter で開いた時点で、元の中身が消えることを説明できる
  • 検査例外は、try-catch か throws を書かないとコンパイルが通らないと説明できる
  • CSV の1行を split で分け、Integer.parseInt で数字にして Product を作れる
